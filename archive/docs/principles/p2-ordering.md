I would order them from ontology, to authority, to computation, to product interaction, to terminal acts and operational constraints.

1. Facts are peers, not document children.

This establishes the system’s basic unit of truth: claims become facts through assertion, not through containment in documents.

2. No new noun without a schema.

Once the basic ontology exists, this governs how it may expand. Nothing becomes a first-class system concept accidentally.

3. Schema is canon.

This establishes what defines every admitted noun and instance. The schema, rather than any consumer, determines meaning.

4. No authoritative state exists outside the workspace.

This establishes where those facts and schema-bound objects live. The workspace is the complete authority, not one store among several.

5. Every change is complete.

This governs how authoritative workspace state may change. No committed state depends on a later operation to become valid.

6. Every value carries its explanation.

Now that state and mutation are established, this requires every value to retain the provenance and reasoning that justify it.

7. Judgment lives with the facts.

This specializes the fact ontology for discretionary choices and establishes the boundary between human judgment and deterministic derivation.

8. Derivation logic is legible data.

This establishes the machinery the user adopts: versioned, inspectable rules containing all operative tax meaning.

9. Derived facts carry their contract.

This explains why facts produced by that machinery are authoritative and how their provenance, applicability, and supersession work.

10. Computation publishes facts.

This establishes execution: the runner discovers eligible derivations, publishes complete facts, and continues until saturation or a declared boundary.

11. A run leaves a record.

After defining execution, this defines its durable account: what ran, what was published, what was blocked, coverage, and termination.

12. The workspace is always reachable.

The document can now move from internal architecture to product interaction. All of the established workspace state remains accessible regardless of flow.

13. The user controls the context.

Reachability alone is insufficient; this principle governs which reachable state the system selects and uses for a particular task.

14. Filing is an assertion.

This defines the terminal user act that converts a derived filing view into a fixed historical record.

15. Synthetic by default; personal data is quarantined.

I would place this last because it cuts across the entire system rather than extending the ontology or computation sequence. It governs how the architecture is developed, tested, demonstrated, and operated.

The resulting progression is:

facts → nouns → meaning → authority → valid change → explanation → judgment → derivation rules → derived authority → execution → execution record → access → context → filing → data discipline

One possible adjustment is to place “Every value carries its explanation” immediately after “Facts are peers.” That would foreground the product thesis earlier. The ordering above instead prioritizes architectural dependency: first establish what exists, what defines it, where it lives, and how it changes; then establish how it explains itself.
