# Citation Walk — Cycle 5 (Builder B) — Accessibility & Legibility Notes

## Choices and how a checker can verify each

| Choice | How it's implemented | Automated check |
|---|---|---|
| Landmarks | `<header>`, `<nav aria-label>`, `<main id="main-content">`, `<footer>` | Query landmark roles (`header`,`nav[aria-label]`,`main`,`footer`) — exactly one `main`, `nav` has accessible name |
| Section structure | Each line/part is a `<section aria-labelledby>` pointing at its own `<h2>`/`<h3>` id; heading levels nest (h1→h2→h3) with no skips | Walk headings, assert monotonic nesting; assert every `section[aria-labelledby]` id resolves to an existing element |
| Keyboard-reachable citations | Citations are native `<details><summary>`, not `div`+`onclick` — keyboard-operable (Enter/Space) with no JS needed for basic toggle | Tab through page, assert `summary` elements receive focus in DOM order and `Enter` toggles `details[open]` |
| Visible affordance cue | Each `summary` shows a static `▸` marker (rotates on open) plus a persistent text hint "(select to expand citation detail)" — visible at rest, not hover-only | Assert `.affordance-hint` text node exists and is not hidden (no `display:none`/`visibility:hidden`, not gated by `:hover`) |
| Focus-visible | `:focus-visible` rule sets a 3px solid outline (`--focus`) with offset, applied to all interactive elements, never suppressed via `outline:none` elsewhere in the CSS | Grep CSS for absence of unconditional `outline:none`/`outline:0`; programmatically focus each interactive element and read computed `outline-style/width/color` |
| Color contrast | CSS custom properties document approximate contrast ratios inline (e.g. `--ok-fg` on `--ok-bg` ≈ 6.3:1, `--blocked-fg` on `--blocked-bg` ≈ 7.2:1); both light and dark palettes chosen for ≥4.5:1 body text / ≥3:1 large text | Checker computes relative luminance from `getComputedStyle` fg/bg pairs per element and asserts WCAG AA thresholds (4.5:1 normal, 3:1 large/bold ≥18.66px) |
| Blocked-state salience | Line 16 uses a dedicated `role="alert"` banner, red/orange palette distinct from the green "published" palette, an icon, a heading, and a `<dl>` of reason/missing-fact/remedy — no fabricated numeric value, both a hidden and visible non-value indicator | Assert `role="alert"` present, assert no digit characters appear in `#line-16-value`, assert badge class differs from `.published` |
| Reuse legibility (backlinks) | Each citation's expanded body lists "Also cited in: <link>" pointing at the sibling instance's DOM id; clicking moves focus to the target `summary` and expands it | Assert `a[href^="#citation-"]` resolves to an existing `details.citation`; assert click handler sets `target.open = true` and moves `document.activeElement` to target's `summary` |
| Citation identity | One `renderCitation(site)` function is the only code path that emits citation markup; called once per site from a declarative `SITES` registry, so duplicate citations cannot drift | Structural: grep for a single `renderCitation` definition; behaviorally compare `.citation-body` innerText across all sites sharing a `factId` — must be byte-identical for fact fields (id/payer/amount/date/source) |
| Fail-loud, per-section blast containment | Each of the 4 citation containers is rendered inside its own `try/catch`; on failure only that container's `<ul>` is replaced with a `role="alert"` box; sibling containers are untouched (separate DOM subtrees, separate catch blocks) | Force one container's render to throw (e.g. monkeypatch `FACTS` before script load in a test harness external to this file) and assert the other 3 containers still render their expected citation counts |
| Redaction on error | Error banner text is a fixed string; `err.message` is never interpolated into the DOM | Grep source: no `err.message`/`error.message` appears inside `textContent`/DOM-insertion calls |

## Carried contracts — status

1. **Zero-authority / honest blocking**: holds. All four items render only fixed, pre-published values; Line 16 shows no numeral anywhere (verified: `#line-16-value` contains no digits, only the block reason/remedy text). There is no user-input path on this static page, so the specific failure mode "arithmetic computed from tampered input" has no live trigger surface — the per-section `try/catch` isolation is architected so that *if* a future input path existed, a bad value would blow that section's boundary rather than silently compute.
2. **Citation identity under reuse**: holds, structurally. `demo-fact-int-001`/`002` and `demo-fact-div-001` are each rendered exactly twice via the same `renderCitation()` call against the same frozen `FACTS` record; the visible fact fields (id, payer, amount, date, source doc) are therefore identical by construction, not by discipline.
3. **Fail-loud + blast containment**: holds. Four independent `try/catch` boundaries, one per citation container (`line-2b`, `line-3b`, `schedule-b-part-1`, `schedule-b-part-2`); each failure renders a local `role="alert"` box and leaves the other three untouched.

## Tensions / open questions — what I believe is irreducibly human-eye

- **Actual rendered contrast in-context**: the ratios noted in the CSS comments are computed against the flat `--*-bg`/`--*-fg` pairs, but real rendering involves anti-aliased text, border blending, and OS-level color management (especially in dark mode with `prefers-color-scheme` vs. the explicit `data-theme` override). A checker can verify the *declared* pair meets AA, but subtle cases — e.g. does the `▸` glyph itself read clearly at small sizes, does the dashed `.backlinks` border look like a divider or like decoration — need a human glance.
- **"Obviously blocked" as a Gestalt judgment**: I gave Line 16 a red palette + icon + alert role, which a checker can confirm exists, but whether it actually *reads* as more alarming than "published" at a glance (versus merely differently colored) is a design-quality judgment, not a boolean.
- **Backlink discoverability**: the backlink only appears once a citation is expanded (inside `.citation-body`). A checker can confirm the link exists in the DOM, but whether a human notices reuse *before* expanding — i.e., whether the summary line itself should hint "(cited elsewhere)" before opening — is a UX tradeoff I did not resolve. I chose to keep the summary line uncluttered at the cost of one extra click to discover reuse; this is a legibility vs. density tradeoff a human should weigh in.
- **Cognitive legibility of "same citation, identical rendering" as phrasing**: a checker can confirm the backlink text string exists; whether it actually communicates the *guarantee* (identity, not just similarity) to a non-technical reviewer is a wording judgment.
- **Motion/transition subtlety**: the `▸` rotation on open is a 0.12s CSS transition — a checker can assert the rule exists, but whether it's perceptible/helpful vs. distracting (and whether it should respect `prefers-reduced-motion`, which I did *not* add) needs a human call. This is a gap I'm flagging, not one I resolved.

## Known gap I'm flagging, not fixing this cycle

`prefers-reduced-motion` is not respected for the `▸` rotation transition. Low risk (single small transform, no parallax/autoplay) but should be added if this pattern persists past prototype stage.
