# DESIGN — Builder A, Cycle 5 (accessibility & legibility)

Disposable prototype, `walk.html`, single self-contained file, synthetic `demo-*` data only.

## Accessibility / legibility mechanisms and how a checker verifies each

| Mechanism | Implementation | Automated check |
|---|---|---|
| Semantic structure | `<header role="banner">`, `<nav aria-label="Sections">`, `<main>`, one `<section>` per fixture item, each `aria-labelledby` its own `<h2>` id | Query for landmark roles (banner/navigation/main) and confirm each `section` has a resolvable `aria-labelledby` target |
| Color contrast | CSS custom properties with ratios computed by hand (WCAG relative-luminance formula): body text vs bg ≈17.4:1 (light) / ≈15.8:1 (dark); links/citation text ≈10.05:1; PUBLISHED badge white-on-`#1b5e20` ≈7.87:1; BLOCKED badge white-on-`#7a0000` ≈11.49:1; focus outline `#000` vs white =21:1 | Extract `getComputedStyle` colors for each selector, recompute contrast ratio programmatically, assert ≥4.5:1 (text) / ≥3:1 (UI component/large text) |
| Keyboard-reachable citations | Citations are native `<button type="button">` (in-flow tab order, no `tabindex` hacks), toggle `aria-expanded`/`aria-controls` a disclosure `<div role="group">` | Simulate Tab traversal via `document.activeElement`, confirm every `.citation` button is reachable and `Enter`/`Space` toggles `aria-expanded` |
| Visible affordance cue (not hover-only) | Citation buttons always render with a solid 2px border, dotted-underline text, and a 🔗 icon — this is baseline style, not a `:hover` addition | Diff computed style of `border`/`text-decoration` with and without `:hover`/`:focus` state — the persistent styles must already be present in the base rule (verifiable by reading the non-`:hover` CSS rule matching the selector) |
| Distinct focus indicator | `:focus-visible` adds a 3px solid outline + 2px offset, separate from the hover treatment | Programmatically focus each interactive element, read `getComputedStyle(el).outlineWidth/outlineStyle`, assert non-`none` |
| Blocked-state salience | Line 16 section gets a 3px high-contrast border + tinted background at the section level (not just the badge), `role="alert"` on the banner, a ⚠️ icon, bold "Blocked" badge, and explicit block reason / missing fact / remedy text | Assert `[role="alert"]` exists inside `#line-16`, assert the section element has a border-width/background distinct from sibling sections, assert text content includes "Block reason", "Missing contributable fact", "Remedy" |
| Reuse legible to humans | Each citation's expanded detail includes reciprocal `<a class="backlink" href="#other-site-id">also cited in …</a>` links, generated from the same `SITES_BY_FACT` index used to guarantee identity | Programmatically confirm: for every fact cited at N>1 sites, each site's detail contains exactly N−1 backlinks, each resolving (`href` target exists in DOM) |
| Citation identity under reuse | One render path, `renderCitation(siteId, factId)`, builds DOM via a small `el()` helper — no innerHTML, no per-site hand-authored markup | Serialize two citation buttons/details for the same `factId`, strip only the backlink nodes, and diff — must be structurally identical (same tag names, attributes except `id`, same text) |
| Fail-loud / blast containment | Each of the 4 sections is rendered by `renderSectionSafely`, which wraps its renderer in try/catch; on failure it clears *only that section's* container and injects a `role="alert"` error banner naming a static reason class, never the offending value | Not exercised live (see below) but structurally verifiable by static analysis: each `render*` call site is individually wrapped, `container` scope never crosses section boundaries, and rejected/unknown data never appears interpolated into the error text |
| Skip link | `.skip-link` to `#main`, visually hidden until focused | Tab from page top, assert first focusable element's text is "Skip to main content" and it becomes visible on focus |

## Carried contracts — status

1. **Zero-authority / honest blocking**: line 16 has no numeric value anywhere in `FACTS`/`CITATION_SITES`/DOM; the block reason, missing fact, and remedy are the only content shown. Diagnostic subtotal lines (`Subtotal check: …`) only exist for 2b/3b/Sched B and are computed from the same frozen `FACTS` object rendered on screen, not from any external/tampered input. Holds.
2. **Citation identity under reuse**: single `renderCitation()` path, single `FACTS` source of truth, structurally guaranteed (see table row above). Holds.
3. **Fail-loud with blast containment**: per-section try/catch, redacted error text (only a static `err.message` class string — never a rejected value or raw input is echoed). Not fired live in the shipped page (no embedded test harness per constraints), but the isolation is structural: each section owns its own DOM container and its own try/catch, so one failing section cannot mutate or clear another's container. Holds by construction; unexercised in this artifact.

## Tensions / open questions — what likely needs a human eye

- **Actual rendered contrast in context**: the hand-computed ratios assume flat colors against a flat background; things like the badge's rounded-pill anti-aliased edges, focus-ring overlap with colored backgrounds (e.g., outline color vs the blocked section's tinted background), and dark-mode `prefers-color-scheme` fallback values were chosen by formula, not eyeballed in an actual browser under real font rendering/subpixel AA. A checker can confirm the *declared* CSS values pass contrast math; it can't confirm the page doesn't look muddy, cramped, or visually unbalanced.
- **"Obviously blocked" as a Gestalt judgment**: the checker can confirm role=alert and a border-width delta exist, but whether the blocked section actually *reads* as alarming at a glance (relative visual weight vs the three published sections, icon legibility at various zoom levels) is a subjective/holistic call.
- **Backlink UX quality**: a checker can confirm backlinks exist and resolve, but not whether "also cited in Schedule B Part I" is the *clearest possible phrasing*, or whether jumping via anchor link disorients a screen-reader or low-vision user (loss of context, lack of a "return to origin" affordance) — this needs a human (ideally with assistive tech) to walk through.
- **Cognitive load / information density**: the detail `<dl>` is dense (5 fields); whether that's legible/scannable rather than overwhelming, especially for a first-time reader, is a judgment call no automated contrast/DOM checker can make.
- **Motion/timing**: none is used here, but if a future iteration animates the disclosure, "reduced motion" *appropriateness* (not just presence of `prefers-reduced-motion` media query) still needs human judgment.
- **Icon-only meaning without color**: 🔗 and ⚠️ emoji rely on system font rendering; a checker can verify `aria-hidden="true"` is set (so screen readers skip them and rely on adjacent text) but can't confirm the glyph itself renders recognizably on every platform.

## Not exercised in this artifact
No live fault-injection demo is shipped (constraint: no embedded live test harness). The blast-containment mechanism is present and inspectable in source but not triggered on load, since all four fixture items are well-formed per the fixture file.
