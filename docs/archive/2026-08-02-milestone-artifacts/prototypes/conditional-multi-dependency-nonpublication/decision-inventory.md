# Decision Inventory — Conditional Multi-Dependency Non-Publication

Status: **owner-authorized inventory only** (2026-07-18). No prototype plan,
charter, builder, reviewer, implementation, or dispatch is authorized by this
document.

## Trigger and boundary

D2 Confirmation R1 measured that a qualified-positive line-16 rule with two
absent declarations can report only the first absent reference through the
committed evaluator, runner, and NPE walk. The owner directed that this is not
deferred breadth: D2 requires a walk naming all currently required factual
declarations in that branch. The capability is generic, not tax-specific, and
must be decided as its own substrate topic before D2 can conclude.

The topic is limited to **conditional demand for multiple factual dependencies
and honest non-publication reporting**. It does not reopen D2’s worksheet
ladder, declaration domains, present-yes disposition, box-2a admission
interlock, package ownership, Schedule B, statutory tax fidelity, or any
production implementation.

## Gate 0 — Decision inventory

| Id | Candidate proposition | Why it is distinct |
|---|---|---|
| CMDN-P1 | A declared rule can state that, when a declared condition is active, a defined set of factual dependencies is jointly required; if several are absent, its non-publication disposition and explanation name each absent member rather than the first evaluator access only. | Primary semantic and record/explanation proposition; it defines what the product can honestly tell the user. |
| CMDN-P2 | The active conditional dependency set and its missing-member reporting are declared artifact semantics, not runner-specific tax policy or an undeclared post-processing list. | Tightly dependent implementation-boundary proposition; protects Articles 11, 12, and 15. |
| CMDN-P3 | Currency/pinning behavior for a later contribution of any one previously missing member is represented without a third standing-affecting edge or an unconditional dependency demand when the condition is inactive. | Tightly dependent lifecycle proposition; determines whether the representation is compatible with Article 7. |

No additional propositions are admitted. In particular, arbitrary validation
aggregation, form-level error presentation, optional defaults, and multi-form
orchestration are out of scope.

## Required next decision

Before any prototype charter, prepare an owner-approved topic plan that
discharges Gates 2–8. Its paper cases must include: condition inactive with all
members absent; condition active with zero, one, and multiple members absent;
partial contribution followed by re-run; all members present; supersession of
a present member; and a proof that no tax-specific runner branch or third
currency edge is introduced.
