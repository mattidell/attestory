## Measure 2 — §C.8 push independence
**Decision-blocking (incumbent).** §D1-P1(c) rung 2 scopes the push scan with `rev-list <sha> --not --remotes`. That keys the scan on remote-tracking refs — exactly the "diff / dependent-on-remote-tracking-state" mechanism §C.8 and the charter forbid ("independent of remote-tracking state and visibility — not a diff from `main`"). §C.8 holds "anything ever pushed is treated as potentially world-readable"; a commit already reachable from any remote-tracking ref is excluded from re-scan, so the outgoing envelope is not scanned in full. Case 3's `--no-verify` probe exercises commit-gate independence but not remote-state independence. The tag-annotation (R7) and ref-name additions are sound; the base walk is not.
**Not-blocking (rival).** §3 push surface consumes "the exact local ref/object pairs supplied to the transport," scans the entire reachable graph per outgoing ref, and "does not rely on remote-tracking state, visibility, branch type, or a diff from `main`." Interim private-remote posture explicitly non-load-bearing (examination: "current private-remote posture and ignored directories carry no part of the proof"). Conforms.

## Measure 3 — Structural vs procedural (Article 18)
**Not-blocking (rival).** §1/§3 name a directional structural wall (publication env has no capability to read `L`), and state plainly "a bypassable advisory hook alone does not satisfy Article 18," with guarded transport + hook integrity named as production conditions. Honest.
**Not-blocking, with defect noted (incumbent).** Hook bypass is named honestly ("git hooks are per-clone and bypassable… rung 2 is the boundary, rung 3 is the alarm"; entrypoint coupled to hook presence). But §D1-P1(a) L2 calls the ignored-root pointer "the audited non-route" and frames residency containment as "structural." Under Ontology §8 an ignore is a procedure, not a wall ("no recorded permission substitutes for a missing wall"). Overstating a convention as structural is an honesty defect; its consequence is scored under Measure 6.

## Measure 4 — Sensitivity inheritance
**Decision-blocking (incumbent).** The may-cross predicate is *class + content screens* (R4/R4b/R5), which key only on values, markers, and absolute paths. CONTRACT class (reviews, process logs, retrospectives, and per surface 11 "live-run reports [that] cite dispositions") therefore passes even when it *describes* a real run. Ontology §8 sensitivity inheritance is explicit: a record "is as sensitive as what it describes," disposition metadata included — "'it's just metadata' is never an exit visa." A synthetic-illustrative review stating "line 2b blocked because the real 1099-INT box 1 was absent" carries no value/marker yet discloses the workspace's shape and would pass the incumbent's screens. The classifier structurally cannot catch description-based sensitivity. (Milestone Verification's "report (dispositions, not values) is what reviews cite" partially licenses this and conflicts with Ontology §8 — a doc-vs-doc conflict the owner should reconcile; but the governing doctrine is sensitivity inheritance, and the incumbent's mechanism cannot enforce it.)
**Not-blocking (rival).** §2 rule 1 makes personal provenance *or description* → `NEVER_CROSSES`; "a review derived from live dispositions is personal and never crosses even when amounts are omitted… only non-descriptive action attestation may cross." Conforms to Ontology §8.

## Measure 5 — E18.3 discharge
**Not-blocking (both); rival stronger.** E18.3 requires a fixture provenance manifest naming generator + constraints. Incumbent §D1-P2: mandatory manifest (generator, seed, constraints; R2 rejected the manifest-less fixture in probe) plus a runnable token-intersection screen — discharges E18.3 and adds a screen; byte-regeneration absent (above E18.3's bar). Rival §D1-P2.2: manifest pins generator id/version + digest, grammar/profile digests, seed, constraints, and "the gate recomputes the fixture from those pins and requires byte equality" — a runnable byte-regeneration check that exceeds E18.3. Both discharge the recorded debt rather than restate it.

## Measure 6 — Locator model (decision-blocking divergence)
**Authority note (per stop condition):** ADR-0030 §C.8 does *not* literally contain "no load-bearing ignore"; §C.8 forbids the interim *private-remote posture* being load-bearing. The rule that an ignore is not a wall comes from Art. 18 / Ontology §8 ("structure where structure can hold it; grants complement walls, never replace them"). I judge the ignore against that authority, not an invented §C.8 clause.
**Rival — conforms.** §1 commits *no* locator ("no concrete locator, locator fragment, canonicalized path, hash of a path, or owner-local identifier is committed"); the run receives an explicit runtime capability. Nothing in the tree, no ignore doing privacy work. Unconditionally conformant.
**Incumbent — decision-blocking as offered.** L2 offers env-var *or* an ignored-root pointer file (`local-data/workspace-pointer.json`) as equals. The env-var variant conforms (nothing in tree). The ignored-root pointer file holds the residency locator and depends on `.gitignore` to keep it untracked — the ignore carries privacy weight, i.e. it *is* load-bearing, unless the R1 (force-add) and R4 (absolute-marker) screens fully backstop it at *every* surface including push. Because the push gate is unsound (Measure 2), that backstop is not guaranteed on the publication surface, so the pointer-file variant is a load-bearing ignore that violates Art. 18 / Ontology §8. **Conformance condition:** an ignored-root pointer conforms only if its locator is independently rejected by a structural content screen at both commit and push, so the ignore is convenience not wall; met by env-var-only, unmet by the pointer file while the push gate keys on remote state.
