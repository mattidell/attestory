`inventory.py` in this directory. `inventory.json`, `reproduction.json`, and

function assigns that target in a `finally`.

## Design

One loader under `tests/`, used for every in-process evidence load, including
loads nested inside a harness.

The loader keeps a context variable keyed by the test module that owns the
load. An import whose file is under a `*-evidence` directory misses the bare
`sys.modules` entry and is cached under that owner plus the resolved path.
`packages.*` and `tests.*` stay shared. A meta-path finder, or an equivalent
overlay installed for the duration of the load, has to see `import probe` and
`importlib.import_module("probe")`. Unique names on `spec_from_file_location`
alone leave those inner imports shared. Re-executing the top file under a new
name took 0.003s and left `probe` and `cf_prototype` as the same objects.

A harness whose transitive closure assigns a `packages` attribute, and whose
function does not assign that target again in a `finally`, loads in a
subprocess. Private copies do not isolate `packages.tax.loader`. The sticky
flags `_cf_patched` and `_codeb_patched` return early on the next call, so a
later test on the same worker keeps the replacement.

A harness that only writes other harness globals, or that restores engine
writes in a `finally` (`audit_harness.loader_entries`, `codeb_globals`), stays
in-process under the private cache. Pytest runs one test at a time on a
worker, so the `finally` has finished before the next test. A test that ran
inside that window would still see the temporary values.

Track 1, not this unit, owns the test that fails when a test loads an evidence
file by any path other than the loader. That test should treat the seven
unreached engine-writing files as subprocess loads when a test starts loading
them.

`tests/test_noncovered_sales_v79.py` inserts the evidence directory and calls
`import_module` for `p0b`, `probe`, `prototype`, and `track0`. Those calls
have to go through the loader.

Subprocess loads that are already isolated (orientation, foreman context,
envelope posture, and the export scripts some live tests spawn) stay as they
are. The eight modules that load a tool or another test are outside this
milestone's harness list.

## Cost

Cold interpreter, three repeats, two modules: `codeb_prototype.py` (subprocess
candidate) and `audit_harness.py` (private candidate). Median wall seconds:

| Load | Wall | Inner import |
| --- | --- | --- |
| Both files, one process | 0.344 | 0.290 |
| Same, then a second top-level exec under new names | 0.344 | 0.286, then 0.003 |
| `codeb_prototype.py` in its own process | 0.338 | 0.284 |
| `audit_harness.py` in its own process | 0.177 | 0.128 |
| The two subprocesses added | 0.515 | |

Two cold subprocesses cost about 0.17s more than importing both files in one
process. The interpreter adds about 0.05s on top of each import. The fast
code B package module finishes in 0.28s in-process today. This unit does not
change the fast-lane budget. `cost.json` holds the repeats.

## Decisions for the foreman

1. Use the split above: subprocess for the four modules, private copies for
   the sixteen, and no move for the three isolated loads or the eight
   non-evidence loads.
2. The loader has to intercept nested bare imports. Rewriting only the outer
   `spec_from_file_location` name leaves `import probe` shared.
   `tests/test_noncovered_sales_v79.py` has to call the loader.
3. Restored engine writes (`audit_harness.loader_entries`, `codeb_globals`)
   can stay in-process. The sale-family cluster is in the private list on
   that basis.
4. The seven evidence files that write engine state and that no current test
   reaches should become subprocess loads if a later test imports them. The
   Track 1 guard is the place that pins that.
5. Leave the fast-lane budget where it is. The one fast module on the
   subprocess list runs in 0.28s today, and a cold subprocess of its harness
   import measured 0.338s.
