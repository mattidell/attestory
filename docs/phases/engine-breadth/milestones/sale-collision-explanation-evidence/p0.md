## 2. Current Saved-Page Behavior on Core `v106`

### 2.1 Why `resolved.reasons` is Empty Today (`file:line` Trace)

1. **`packages/derivation/runner.py:1863-1916`**: `_evaluate_family_validation` checks each `excl` in `identity_exclusivity`. Neither `IDENTITY_EXCLUSIVITY_COLLISION` nor `identity_exclusivity:<excl_id>` matches, so `explain` returns `False`.

## 4. Design & Wording Comparison

### 4.1 Projection Handling (`packages/derivation/presentation_projection.py`)

In `_closure_question_reasons` (`explain(current, key)`), gated by `explains_identity_exclusivity_collision(package_id, version)` (`core-calculations >= v106`) in `packages/tax/loader.py`:
- Match ONLY when `artifact.endswith(".member-validation.synthesized")` **and** `"IDENTITY_EXCLUSIVITY_COLLISION" in (current.get("missing") or ())`.
  - Leaves `IDENTITY_COMPONENT_MISSING` (`runner.py:1907-1909`) and `IDENTITY_EXCLUSIVITY_FAMILY_ABSENT` (`runner.py:1868-1871`) failing closed.
- Handle **both** tokens cleanly:
  - When `key.startswith("identity_exclusivity:")`: resolve `excl_id = key.removeprefix("identity_exclusivity:")` against `members_by_id.get(family_id, ())` (`identity_exclusivity` entries) to find `incompatible_family["id"]`. Emit the pair sentence (or generic fallback if unmapped) into `frames[-1].extras` and return `True`.
  - When `key == "IDENTITY_EXCLUSIVITY_COLLISION"`: if all `identity_exclusivity:*` entries on `current["missing"]` resolve to pair sentences, return `True` without adding a duplicate generic bullet; otherwise add the generic fallback sentence to `frames[-1].extras` and return `True`.
- **Deduplication:** `frames[-1].extras` is a `set[str]`. Sorting the two plain category labels `(first, second) = sorted((label_a, label_b))` guarantees that even if two families declare symmetric mutual exclusivity (`A -> B` and `B -> A`) and both block simultaneously, both emit the identical sentence and collapse to **1 bullet**.

### 4.2 Wording Comparison: Generic vs. Pair-Specific Plain Labels vs. Content Citizen

Note first: raw `source-family` `title` metadata cannot be interpolated directly because titles mix capitalization, pluralization, `"gain-or-loss"` / `"transactions"` vs. `"sales"`, and `", tax year 2025"` suffixes, and `noncovered-*` titles omit `"Form 1099-B"`.

| Dimension | **(a) Single generic sentence** | **(b1, Recommended) Pair-specific closed map in `packages/tax/loader.py` + generic fallback** | **(b2) Content citizen (`v107` / new schema + ADR)** |
| --- | --- | --- | --- |
| **Filer clarity** | Clear that the same sale is in two categories, but does not name *which two* (harder on multi-sale or cross-term collisions). | **Highest without core bump:** Names both colliding categories plainly (e.g. `"a short-term covered Form 1099-B sale (no adjustment)"` and `"a short-term covered Form 1099-B wash sale (code W)"`) with zero `"family"` or engine-id leaks. | Same clarity as (b1), stored in package JSON. |
| **Truthfulness & edge cases** | True for all 18 pairs and collapses 3-way collisions to 1 bullet. | True for all 18 pairs; symmetric pairs dedupe to 1 bullet; 3-way lists each colliding pair; unmapped future pairs fall back cleanly to (a). | Same as (b1). |
| **ADR-0066 & maintenance** | 100% domain-neutral; zero family-id table in Python. | Keeps `packages/derivation/presentation_projection.py` 100% domain-neutral (receives `collision_sentence` and `collision_category_labels` kwargs); places the 8-entry `SALE_COLLISION_CATEGORY_LABELS` map in `packages/tax/loader.py` alongside `COVERED_FLAG_REFUSAL_SENTENCE`. Needs updating only when a new sale family adds `identity_exclusivity` (otherwise falls back to (a)). | Package-validated JSON citizen; no Python tax-label table. |
| **Schema / core / ADR impact** | None (`v106` stays `v106`, `presentation-model.v3` unchanged, no ADR needed). | None (`v106` stays `v106`, `presentation-model.v3` unchanged, no ADR needed). | **Requires** schema/package bump (`v107` / registry `v105` / release `v105`), `package_validation.py` changes, and a new ADR. |

**Recommendation:** **Option (b1)** — `SALE_COLLISION_CATEGORY_LABELS` (8 Form 1099-B sale categories) + `IDENTITY_EXCLUSIVITY_COLLISION_SENTENCE` generic fallback in `packages/tax/loader.py`, gated to `core-calculations >= v106`, passed into `_closure_question_reasons` in `packages/derivation/presentation_projection.py`. It delivers pair-specific filer clarity with zero schema, core, kernel, `runner.py`, or HTML changes.
