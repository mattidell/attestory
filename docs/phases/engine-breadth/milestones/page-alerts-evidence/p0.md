Published core v91 (registry v89, release v89). Scratch core v92 is a content
successor of that core, built by `prototype.py` outside the repository.
`packages/` was not edited. The saved page is
`packages/presentation/pages/citation-walk.v1.html`, opened in headless
Chrome 157.0.8103.78 (node 22.23.2).

## Result

Both parked alerts reproduce. A content successor clears both on the drawn
pages. The recorded replay changes no number and asks no new question. The
repair does not need an engine, schema, projection, page, or kernel change.

When the lump-sum election is made, line 6c still draws "Not applicable."
Those words are false for a checkbox that would be checked. That wording is
left for the foreman. The alert itself is gone in both states.

## Design

The smallest repair is content, and it is what scratch v92 builds.

Line 6c. Successor `rule.form1040-line6c` v2 publishes `not_checked` on the
same scope and the same fact. Successor `form1040.line-6c` v2 renders
`not_checked` and explains "The lump-sum election checkbox is not checked."
The rule entrypoint moves from v1 to v2. The field stays a member. The
existing line 6c citation stays.

Words the page shows, measured on v92:

- Election not made (the scope fact is `yes`). Value "not checked". Explain
  "The lump-sum election checkbox is not checked." One citation button. The
  model has no pin label, so the button label is
  `tax.us.2025.citation.form1040.line-6c@v1`. These words are true: the
  field is the checkbox, and the fact says the election was not made, so
  the box is empty.
- Election made (the scope fact is `no`), with or without a benefit
  statement. Value "Not applicable." Explain "line 6c disposition is
  inapplicable for the current class". No citation button. No alert. These
  words are false: the checkbox applies and would be checked.

Schedule 1. New citation `tax.us.2025.citation.schedule1.top-entry` v1,
authority family `irs-instructions`, form `1040-SCH-1`, tax year 2025.
Successor `schedule1.top-entry.form-field` v2 carries that citation. The
field entrypoint moves from v1 to v2. The publishing rule stays v3.

Words the page shows, measured on v92:

- No Form 1099-K. Value "0". Explain "No Form 1099-K statements were
  received for 2025." One citation button, labeled
  `tax.us.2025.citation.schedule1.top-entry@v1`.
- Personal-item loss, Box 1a 880. Value "880". Explain "This sale resulted
  in a nondeductible personal loss whose Box 1a gross amount is entered at
  the top of Schedule 1." Eighteen citation buttons: the new field citation
  plus the source-fact sites the numeric renderer already draws for that
  section.

A second line 6c field, on the line 6d pattern, would publish `checked`
when the fact is `no`. The unelected state would keep "not checked" here
and "Not applicable." on the sibling. The elected state would show
"checked" on the sibling and "Not applicable." here. Both affirmative
words would be true. The cost is an extra section on every return, and a
second rule on the same fact. An unanswered fact would block twice, and
the questions list can gain another copy of the question. v92 leaves that
sibling out so the rerun can show that no return newly asks a question.

A page change could draw the string `not_elected`, or could word this
field's inapplicable state as "checked". That is a renderer change. It
overlaps the open blocked-sale-pages milestone. It is not required to
clear either alert.

`prototype-build.json` records the successor. It reports no inherited
inconsistency.

## Recommendation

Adopt the v92 content successors: `rule.form1040-line6c` v2,
`form1040.line-6c` v2, `citation.schedule1.top-entry` v1, and
`schedule1.top-entry.form-field` v2. That clears both alerts. The unelected
checkbox reads "not checked", which is true. The top entry shows its
amount, where the amount comes from, and a citation.
