# P0: which unconfirmed families do not ask their question

Builder unit on `milestone/closure-question-coverage-2025` at `c8f17430b540a3b8707a6f1cbc9abb4e2281d08b`.
Core v74. Evidence only. No production, test, content, or schema edit.

## Scope

A line blocked because a statement family's completeness is unconfirmed names that family's completeness question. The two covered wash-sale transaction families are the known cases. This survey finds the rest. A fix, if one is designed here, is a successor rule or mapping, or a declared question, prototyped outside the repo. Confirmed families stay byte-identical to v74.

## Evidence ceiling

`live_coordinate_run` on the committed core v74 package. One publishing return. For each source family the package's closure mappings name, the closure assertion alone is removed, with members and with none. Root codes come from the saved dispositions. Whether the line names the question comes from the saved presentation model.

## Stop conditions

Stop without a content edit if the fix needs a schema, an expression operation, a projection change, or an engine change. List a missing or misleading question and do not reword it. No production, test, content, or schema edits in this unit.

## Method

`probe.py` reads the closure mappings adopted by `package.core-calculations.v74.json`. The return is the publishing Form W-2G base. Each run is `live_coordinate_run` on that package, release `demo.release.sli-worksheet-integration.2025.v72.json`, and registry `published-packages.v72.json`. Variant `none` drops that family's member transitions and member-fact assertions, then removes only its closure assertion. Variant `members` keeps the existing member or adds one synthetic `demo.p0.*` member (with the companions and scope answers that member needs), then removes only its closure assertion. A blocked line is about the family when a root's missing id is the family id or begins with that id. The line names the question when the mapping's `closure_question` is one of the presentation reason sentences. Results are `probe-output.json`.

The unmodified base blocks no line. A few families are not read there, so the probe uses a return that does. Form W-2 box 4 and box 6 use the Schedule 8812 Part II-B return. Gambling losses are read after one closed Form W-2G winning is recorded, which is when Schedule A line 16 reads that family. The other-dependent rosters are read after `ctc.no-other-dependent` is `no`. Form 1099-INT box 8 is read after `line2a-scope.no-f1099int-tax-exempt` is `no`. Form SSA-1099 benefits is recorded on a v1 chain; the v74 handover moves that chain to v2 and is left unreconfirmed, so the removed closure is not put back.

## 3. Why a family does not name its question

### Covered wash-sale transactions

`tax.us.2025.f1099b.covered-w-st` and `tax.us.2025.f1099b.covered-w-lt` fail the same way with members and with none. Thirty-two lines are blocked. None has a reason sentence. The root code on every line is `DEPENDENCY_ABSENT`.

The direct block is `{family}.member-validation.synthesized`, missing the family id. The same code is on the three subtotal rules (proceeds, basis, adjustment), `rule.attachment.f8949`, `rule.attachment.schedule-d`, and `rule.schedule-d-line1b` (short-term) or `rule.schedule-d-line8b` (long-term). Those consumers are missing `{family}.member-validation`.

The authored subtotal `when` is `require_closed` on the companion family, and its authored `requires` is empty. `accounts_for` reaches the transaction family. That family has `member_constraints` and `identity_exclusivity`, so it is constrained. `compile_validation_graph` appends `{family}.member-validation` to `requires` and synthesizes a producer. The runner records a missing require before it evaluates `when`, so `require_closed` never records `SOURCE_SET_UNCLOSED`. `_evaluate_family_validation` records `DEPENDENCY_ABSENT` missing the family id when the family is not in admissions.

`_closure_question_reasons` names a question only when every root is `SOURCE_SET_UNCLOSED` for a family that has a closure question, or a `DEPENDENCY_ABSENT` leaf whose fact type has an input question. A family id is not an input-question fact and has no blocked child row. The walk returns no sentence.

The wash-sale basis, proceeds, and adjustment families are not constrained. Their blocked lines are `SOURCE_SET_UNCLOSED` and name their questions.

### Form 1099-K with one member

With no member, all 30 blocked lines name the completeness question. The root is `SOURCE_SET_UNCLOSED` missing `tax.us.2025.f1099k`.

With one synthetic box 1a member and no personal-item answers, `sch1-10` and `sch1-top` do not. Their roots are still `SOURCE_SET_UNCLOSED` on `rule.schedule1-line10` and `rule.schedule1-top-entry`. Both rules are selections. The blocked reason they attach is the unresolved value `single-sale-unanswered`: "The question regarding single item sale scope has no current answer." Selection reasons are written before the closure-question walk, so the completeness question is not attached. The other 28 lines still name it.

## 4. Smallest fix

No successor rule, mapping, or declared question makes the wash-sale lines name the question. A successor that still reaches the constrained family gets the same injected `.member-validation` require. An input question cannot pin a family id: package validation rejects an input question whose fact type is not on the package fact surface. Dropping `member_constraints` or `identity_exclusivity` would change validation after the family is confirmed.

The change that names the existing question is an engine change. When the family has not been admitted, record `SOURCE_SET_UNCLOSED` missing the family id, which is what `require_closed` would have recorded, instead of `DEPENDENCY_ABSENT`. The presentation already copies that family's closure question for a `SOURCE_SET_UNCLOSED` root. Once the family is admitted, validation is unchanged. This unit does not make that change.

The two Form 1099-K lines are a projection change if they must also name the completeness question while the selection is explaining an unresolved statement. The completeness question is already named when no member is present. No content successor is designed for that case.

No scratch v75 was built. No committed fixture or golden moves. The lines that would gain the question were not counted on a prototype. The live runs show 32 blocked lines for each wash-sale family, and none of those lines names the question.

## 5. Question wording

No closure question is missing. Every one of the 51 questions is a non-empty completeness question, and each one matches its family's closure claim, with two exceptions. Those two are listed and not reworded.

`f1099b.covered-w-st-adjustment` asks: "Have you recorded the wash-sale loss adjustment amount (a loss disallowed because you bought the same investment within 30 days before or after the sale) of every covered short-term sale on every Form 1099-B you or your spouse received for 2025?"

`f1099b.covered-w-lt-adjustment` asks the same of every covered long-term sale.

The family claim is the wash-sale adjustment scalar family. The sibling basis and proceeds questions limit themselves to sales that have a wash-sale loss adjustment. These two questions ask for an adjustment amount of every covered sale.

## 6. Limitations

The survey uses one publishing return, the Part II-B return for the two Form W-2 withholding families, one closed Form W-2G winning so gambling losses are read, and an unreconfirmed Social Security handover for that family only. Other guarded paths were opened only by the scope answers named in the method.

`collect` on a nonempty set does not consult closure. A line that reads the family only that way publishes once a member exists, so it does not ask the completeness question. The Form W-2 member run is the measured case: 34 blocked lines with no member, 6 with a member.

A bare Form 1099-K member is not a supported personal-item loss. The two Schedule 1 lines therefore show the statement's unresolved reason. A fully answered statement was not built.

`scheduleb.adjustment.nominee` with no member blocks a subtotal and no presentation line.

No prototype was run, so confirmed returns were not compared byte for byte with a successor. This unit edits no production, test, content, or schema file. The full suite was not run.
