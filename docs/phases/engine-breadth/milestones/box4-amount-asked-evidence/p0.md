# P0: the box 4 amount is already asked

Date: 2026-11-15. Published baseline: core v91, package registry v89,
release v89. No scratch successor was built. Nothing in `packages/`
changed.

## Result

A Form 1099-B sale with no box 4 amount blocks Form 1040 lines 25b and
25d, and every line blocked through them, on
`f1099b.statement-box4-withholding`. The presentation already shows the
published amount prompt on those fields. Entering the amount, including
$0 when box 4 is blank, publishes line 25b and line 25d. The useful
outcome in the plan is already true on v91.

No new input-question citizen, no `rule-artifact.v17` successor, and no
projection change. The per-statement prompt does not name the statement.
Two statements are still answerable from the published wording.

## Reproduction

presentation projection. Age and blindness are stated false. `probe-output.json`
records, for each case, the box 4 answers on the list, the watched lines,
and every blocked field whose missing-name walk reaches the amount fact
or the W-2 box 2 fact. The page has the amount sentence when any blocked
field's reasons include it. The run used 9 workers and took 29.8 seconds.

## Trace

The question is not lost. The walk ends on the amount fact, and the
projection copies the prompt for that fact.

1. `rule.form1040-line25b` v8, schema `rule-artifact.v15`, is the v91
   member (`package.core-calculations.v91.json` line 6812). Its `when`
   pairs on `f1099b.statement-box4-withholding` for the eight sale fact
   types (`rule.form1040-line25b.v8.json` lines 455-469).
2. `_require_paired` reads keys only. An income key with no withholding
   row raises `DEPENDENCY_ABSENT` and names the withholding fact
   (`packages/derivation/evaluator.py` lines 844-887).
3. The rule's `requires` are present, so the runner does not record that
   requires list. The fallback evaluation records `exc.missing`, which is
   the amount fact (`packages/derivation/runner.py` lines 3055-3086 for
   the requires branch that this row does not take, and lines 3104-3109
   for the branch it takes). The live row's `missing` is exactly
   `f1099b.statement-box4-withholding`.
4. Nothing in the v91 package publishes a blocked row under that fact.
   The amount-symbol rule that published 0 under the amount id is a
   member of cores v83 through v85 only.
5. `_closure_question_reasons` indexes `input-question` members by fact
   id (`packages/derivation/presentation_projection.py` lines 526-528).
   A `DEPENDENCY_ABSENT` name with no blocked child, whose fact is in
   that index, adds the prompt (`reach_mixed`, lines 578-586). The
   adopted prompt is `input-question.f1099b-box4` v1.
6. `rule.form1040-line25d` v1 requires `payments.line25b`
   (`rule.form1040-line25d.json` lines 2-9; package pin at
   `package.core-calculations.v91.json` line 5024). The line 25d row
   walks into the line 25b row and picks up the same prompt.

The yes/no prompt in
`input-question.f1099b-statement-box4-withholding-reported.json` names
`statement-box4-withholding-reported`. Line 25b v6 paired on that fact.
Line 25b v8 does not.

The v90 table in preferential-base-reason stored a question only when the
sentence contained `?` (`preferential-base-reason-evidence/probe.py`,
`_questions`). The amount prompt has no question mark. That filter is why
the table says lines 25b and 25d show no question. The projection stores
the imperative on the field.

### Where the v83 claim holds

The roadmap says a statement with a sale and no amount blocks line 25b
with its question (`docs/phases/engine-breadth/engine-breadth-roadmap.md`
lines 705-708). On v91 that holds for every plan list that has a sale and
no amount: line 25b's only reason is the amount prompt, and line 25d
shows the same sentence. On a covered sale whose other answers are in,
lines 33, 34, 35a, and 37 show only that prompt. A return with no Form
1099-B publishes line 25b as 0 and is not asked the per-statement amount.

Recording reported "no" does not by itself publish the line. The prompt
says to enter $0 when box 4 is blank, and the live row keeps blocking
until that amount exists. Entering $0 publishes line 25b as 0 and line
25d as 4,500.

## Design

The smallest repair is to leave the published content.

An input-question citizen for `f1099b.statement-box4-withholding` is
already a v91 member, and the projection already attaches it. A second
citizen for the same fact would occupy the same fact-id slot in
`_closure_question_reasons`.

A `rule-artifact.v17` block that declares `missing:
[f1099b.statement-box4-withholding]` would name the fact the live row
already names. The requires list is not what the row records, so a
declaring block is not what puts the fact in front of the projection.

A projection change would edit `presentation_projection.py` to attach a
sentence the walk already attaches. That file is in the open
blocked-sale-pages milestone. It would be an engine change with nothing
for the filer to gain.

The prompt does not name a statement. On `two_statements_one_amount` the
six fields show one sentence and no statement id. The wording says to
enter the amount for each recorded sale, and $0 when box 4 is blank.
Recording 150 and 40 publishes line 25b as 190. A filer with two
statements can answer. The page does not say which statement is missing.
Naming the statement stays parked.

Do not open a content track. Do not change the projection, the page, the
schema, or the kernel. The foreman can close the milestone on this
evidence, or record that the v90 "no question" table was the `?` filter.

- The three recorded lists had answered the yes/no. The amount was what

- Form 1099-K box 4 and the return-level total stay as published.
