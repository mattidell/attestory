## Law

Quotes, line numbers, and checksums are in `law.json`. Instruction line
numbers are from `pdftotext -layout`. The Form 1099-B line numbers are from
`pdftotext` in reading order, because layout splits the recipient sentence
at a page boundary. The checksums match the PDFs the box 7 milestone recorded.

A box 7 loss is wholly disallowed. Schedule D Example 2 (instructions lines
287–305) is proceeds $1,000, basis $5,000, box 7 checked, and "your loss of
$4,000 isn't allowed." Form 8949 gets box A or B, or box D or E, whichever
applies. Column (d) is $1,000, column (e) is $5,000, column (f) is L, column
(g) is $4,000, and column (h) is zero ($1,000 − $5,000 + $4,000). The code L
row (Form 8949 instructions lines 603–607) says the same thing for a
nondeductible loss other than a loss indicated by code W: report the sale on
Form 8949 and enter the nondeductible loss as a positive number in column (g).

No sentence allows part of that loss. The recipient instruction (Form 1099-B
lines 633–638) says you cannot take a loss based on the box 1d proceeds, and
that the broker should advise you of any losses on a separate statement. The
separate statement is how the filer learns the nondeductible amount. It is
not an allowed portion, and Example 2 does not ask for a second number.

What can be allowed:

- A gain on a checked statement is not a loss. The recipient instruction does
  not disallow it.
- Column (h) of exactly zero is not a loss.
- A loss on a statement whose box 7 is not checked is allowed, subject to the
  $3,000 capital-loss limit (Schedule D instructions lines 184–188).
- A code B correction that removes the loss leaves nothing for code L.

Code W and code B on the same sale as code L are not exemplified. More than
one code is entered in alphabetical order with the net adjustment in column
(g) (Form 8949 instructions lines 515–524). The arithmetic is a foreman
decision below. Example 2's amount follows from the proceeds and the basis
already recorded, plus the existing box 7 answer. No new amount question is
required for that case.

The broker instructions (lines 215–229) leave the other boxes blank unless
the broker combines the two reporting regimes, and then box 1e must not
exceed box 1d. Example 2 still shows a statement with both amounts and a
loss. The product's per-sale proceeds and basis can express Example 2.

## Design, and the stop

The code L row for Example 2 is settled. A covered sale whose basis was
reported to the IRS uses box A or box D, so the zero column (h) posts to
line 1b or 8b, not to line 1a or 8a. Column (f) is L. Column (g) is basis
minus proceeds. Column (h) is zero. The existing box 7 question stays. An
unanswered box 7 still blocks and asks that question; line 16 v4 already
says so. There is no allowed-portion question.

A gain beside a loss on the same checked statement is allowed. Only the loss
is code L. `yes_loss_beside_gain_same_statement` shows that v85 nets them on
line 1a and then refuses the whole return, including the gain.

Code W: the recommended reading is that code L's exclusion covers the
wash-sale piece already indicated by code W, and the recipient instruction
still forbids the remaining loss. Codes `LW`, code L's amount equal to the
loss left after the wash, net column (g) equal to basis minus proceeds, and
column (h) zero. On `yes_loss_with_code_w` that is a wash of 400, a code L
amount of 600, and net column (g) of 1000. The other reading, that any code
W row keeps the remaining loss deductible, would let a checked statement
produce a deductible loss. Example 2 does not support that.

Code B: column (e) stays the basis shown, and code B's column (g) is the
correction. If column (h) is still negative, code L disallows that remaining
loss. Codes `BL`. On `yes_loss_with_code_b` the correction is 500 and the
code L amount is 500. If the correction removes the loss or turns it into a
gain, code L does not apply. That is the existing code B path. It is not a
new way to allow part of a box 7 loss.

What stays refused until the row exists: a checked loss, exactly as v85
refuses it. Replacing that refusal with a silent zero on line 1a would keep
the loss off Schedule D and still would not be the Form 8949 row.

`prototype.py` writes `prototype-stop.json`. It does not generate a core.
The published Form 8949 attachment validates. Adding a `where` filter on
`collect_members` is rejected. Adding an adjustment kind of code L is
rejected. Setting the adjustment sign to positive is rejected. Using
`enumerate_published` as a positive itemization row on attachment-rule v11
is rejected, because those rows still require `collect_members`. An
adjustment row of a published kind may use `enumerate_published`, and that
fragment validates, but the sign stays negative and the collector emits
`finding_id` and `value` only. It does not emit column (f).

Cause: a Form 8949 row here is a recorded family member. The code L amount
can be computed with operations the package already has. The row cannot.
Moving a covered sale out of the line 1a family when box 7 is yes is not a
rule. The attachment cannot select that sale, and it cannot name code L.

Smallest change: a recording-surface change, then content. When box 7 is yes
and column (h) before code L is negative, record that sale in a code L
family the way a code B sale is recorded, with the proceeds, the basis
shown, and the code L amount computed from those amounts and any wash or
code B adjustment already recorded. A successor attachment itemizes it. The
successor Schedule D lines pick up column (h), which is zero. No new filer
amount, no kernel change, and no edit of a published schema. The other
sufficient change is a new attachment schema that itemizes one derived sale
as columns (d) through (h), plus a line rule that drops that sale from line
1a or 8a. That is a schema and a presentation change.

No scratch core v86 was generated. Earlier milestones' harnesses were not
run, because there is no successor package to run them against. The rerun of
`tests/fixtures/f1099b_backup_withholding_v83/` was not run. There is no v86
result to classify against v85.

## Recommendation

Stop this milestone's content track. Do not publish a core that only zeros
the loss. Charter the recording-surface change, with the code L family
shaped like code B, and then a successor package.

Decisions the foreman must make:

1. Adopt the recommended code W reading (codes `LW`, code L equals the loss
   remaining after the wash) or name a different one.
2. Adopt the recommended code B reading (codes `BL` when a loss remains
   after the correction; no code L when the correction removes the loss).
3. Confirm a gain on the same checked statement still computes, and that
   only the loss moves to Form 8949.
4. Confirm a covered sale uses box A or box D (lines 1b and 8b), which is
   what "basis reported to the IRS" means in the Form 8949 instructions.
5. Choose the recording-surface change as the next charter, or the new
   attachment schema instead.
6. Leave the box 7 question as it is. Do not add an allowed-portion
   question or a separate-statement amount. Unanswered box 7 keeps blocking
   and asking the question v85 already asks.
