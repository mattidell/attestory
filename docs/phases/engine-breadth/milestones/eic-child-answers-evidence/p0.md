## Result in one paragraph

On v100 a missing per-member answer is never asked, on any of the four
rosters. Every per-member answer the counts read (earned income child age,
residency, joint return, SSN and the tie-breaker answers; child tax credit
under-17, lived-with-you, support and citizenship; the other-dependent
child's TIN; all seven relative answers) leaves 9 to 18 page lines blocked
with no sentence, for one child or for the second of two. The walk stops at
one root tuple shape: the roster count rule blocks `DEPENDENCY_INVALID`
naming the blocked member's subject key, which is neither a family with a
closure question nor a fact type with an input question. Of the three
content routes, an input question per member fact (route 2) and the existing
closure questions (route 3) are not reached. Declared `missing` names on the
count rule (route 1, ADR 0086) do reach a question. A guarded count rule
names the missing answer's fact type, and the page shows that question on
every blocked line, for the earned income and child tax credit tests. But
route 1 cannot name the child (the plan's Decision 1). It cannot reach the
tie-breaker, other-dependent child or relative answers. It names one missing
test at a time. And it changes the explanation of every return with a
rostered child: the count gains inputs, so every downstream finding's
structure and some lines' citations change. Numbers do not change. The
recorded replay passes 773 of 775. The two lists with a child fail on that
structure change only. **Recommendation: content cannot meet Decision 1.
Stop here. The smallest change that can is in the projection's question
walk: follow a blocked member key to that member's own blocked rows, and
label the question with the member's recorded name. It needs a foreman
decision and, in my reading, an ADR.**

**Why the walk stops (file:line).**

- The count rule's `children` path reads `eic.child.counts` as a declared
  subject result. `_declared_subject_values` refuses `DEPENDENCY_INVALID`
  and names the blocked *subjects*, not what they wait on
  (`packages/derivation/evaluator.py:283-285`).
- Each member's own rows are recorded under the symbol
  `<publishes>|<subject fact id>`
  (`packages/derivation/subject_dispatch.py:719`). A missing input on a member
  row is named by its bare symbol (`subject_dispatch.py:782, 805`). For the
  age, residency, under-17 and similar tests no row exists at all: the test
  rule's subject is the answer itself, so an absent answer is no subject.
- The page builds `by_symbol` from the rows
  (`packages/derivation/presentation_projection.py:4805`). For each blocked
  line it calls `_closure_question_reasons` (`presentation_projection.py:4869`, `:4883`).
  The walk is `reach_plain` (`:642-669`) or `reach_mixed` (`:609-640`). A
  member key is not a family (`:620`), has no blocked row of its own
  (`:625`, `:661`), and is not a fact type with an input question (`:664`).
  So the walk returns False (`:639`, `:667`), and `:680-689` attach nothing:
  every root must have a declared question.

## 4. What content cannot do, and the smallest change that can

Content can put a question on the line (route 1), but it cannot name the
child. A reason the walk attaches is `{"sentence"}` copied verbatim from a
declared question (`presentation_projection.py:680-689`). The only reason
label the model carries is `statementLabel` (lender, statement, tax year),
built for statement lines (`_statement_label`, `:207`; validated at
`:5105-5113`). No content can make a static question sentence name a child,
and no declared name can be per-member: ADR 0086 names are static strings.

**Smallest change: a member-aware question walk in the projection.** It
lives in `_closure_question_reasons` (`presentation_projection.py:465`), at
the point where a missing name has no blocked row, family or input question
(`reach_mixed` `:625-639`, `reach_plain` `:661-667`):

1. **Follow a blocked member.** When the name is a subject fact id
   (`<fact type>|<keys>`), and the blocked row's rule declares a
   `reads_subject_results` symbol S whose subject is that fact type, walk
   the blocked rows under `S|<name>` (the member's own rows, named as
   `subject_dispatch.py:719` names them).
2. **Resolve a member row's missing name for that member.** A bare symbol M
   is looked up first as `M|<member>` (for example the tie-breaker row).
   If M is a fact type with an input question, that question is the root
   (the relative tests and the tie-breaker answers name their facts
   directly). If M has no row for the member and M's only publisher is a
   per-subject rule whose subject fact type T has the member's keys, the
   member has no T. So T is the root and T's input question is asked (age,
   residency, under-17, the relative relationship and TIN tests).
3. **Label the question with the member.** The attached reason also
   carries the member's recorded entity label, read from the member key's
   entity (`child=` or `dependent=`) as `_statement_label` reads a lender's.
   Two children missing the same answer get two reasons, one per child.
   That needs one optional reason key. It could be a new `memberLabel`, with
   the validator at `:5105-5113` and the page's existing label prefix at
   `packages/presentation/pages/citation-walk.v1.html:1043-1045`. Or it could
   reuse `statementLabel.statement`, which needs no page change but misnames
   the key.

Plus content: one sourced `input-question.v1` per per-member answer, as
route 2 adds (wording from the instructions, not the placeholders).

Does it change a published contract? The published
`presentation-model.v2.schema.json` types `sections` items as plain objects,
so no schema version is needed. No rule, rule language, package schema or
kernel change is needed, and no recorded number, row or graph changes. Only
lines that are silent today gain reasons. But it changes the presentation
contract in two ways. It changes which blocked causes the projection treats
as answerable, extending the walk the blocked-names-question milestone and
ADR 0086 set. And it adds a member label to a blocked reason, under ADR
0046's honest-blocking, copy-never-compose surface. **In my reading that
needs an ADR** (presentation: a blocked member's question names the
member). The foreman decides; a new ADR waits for the owner. Not built.

An engine alternative is larger. The evaluator could name each blocked
member's own missing answers instead of the member
(`evaluator.py:283-285`). That would change report rows on every blocked
roster and the derivation contract.

Every difference on the 32 failing lists is sorted in
`replay-explain-*.json`. None is a value or disposition change. A record
under an old alias pairs with the same record under the new alias, with the
same kind, attribute and value. On both recorded lists and 27 probe lists,
everything is accounted for: declared changes, count inputs (the new
declared reads on the two count findings and their rows' pins), and alias
moves. The count's input structure changed, so the structural alias of
every downstream finding changes. On a counted-child return that is about
1,500 to 2,700 records per list. **On the three 17-year-old cases where the
child fails a test early (answered, TIN missing, lived-with-you missing),
247 to 587 differences are not alias moves.** They are page citation sites
on 1040 lines 27a and 32 to 37 and Worksheet A lines 2, 5 and 6. Those lines
now cite the child's residency, joint-return and SSN answers. On v100
`all` short-circuits at the failed age test, so they were never read. The
guard reads every test for every child. So route 1 makes those lines cite
answers that did not decide them.

So no recorded or probe return changes a number or newly blocks. But route 1
is not explanation-neutral: it adds inputs to the count on every return
with a rostered child, and for a child who fails a test it adds
citations the outcome does not depend on.

## 6. Recommendation

Content cannot meet the plan's Decision 1, and route 1, the only route that
reaches a question, costs a structural explanation change on every return
with children and still leaves the tie-breaker and other-dependent answers
silent. Stop at P0 (charter scope item 4). Take the member-aware question
walk (section 4) to the foreman as the milestone's design: a projection
change plus sourced member questions, with an ADR before Track 1. If the
foreman instead accepts an unnamed question, route 1 is the content
fallback; it would still need presence rules for the tie-breaker and the
other-dependent rosters, a probe of the child-tax-credit-only roster case,
and the citation change accepted.

## 7. Decisions for the foreman

1. **Projection change or unnamed question.** Plan Decision 1 says a
   child's question names that child. Only a projection change can do it.
   Recommended: the member-aware walk (section 4), with an ADR proposed to
   the owner. The alternative is to waive Decision 1 and ship route 1.
2. **The reason's member label.** A new optional `memberLabel` on a
   blocked reason (validator plus a two-line page change that reuses the
   statement-label prefix) or reuse `statementLabel.statement` (no page
   change, wrong key name). Recommended: a new key. The non-goal
   "no page design change beyond showing a question that already exists"
   then needs your reading.
3. **Scope across rosters.** The same gap is on the child tax credit,
   other-dependent child and relative rosters. The member-aware walk covers
   all four without per-roster rules. Recommended: widen the milestone to
   all four, since they share the fix. Their sourced questions add about 17
   input questions.
4. **One question at a time or all.** With the walk, every missing answer
   of every member can be asked at once (one reason per member and
   question). Route 1 can ask only one. Recommended: all at once.
5. **ADR scope.** Whether following a member key in the walk and copying an
   entity label into a reason extend ADR 0046 and ADR 0086 enough to need a
   new ADR. My reading is yes. Governance was not read (charter); if the
   answer turns on governance text, escalate to the owner.
