## Trace

`trace_reach.py` prints the reach and writes `trace.json` beside it. Run it from the repository root:

```sh
python3 docs/phases/engine-breadth/milestones/seed-generator-independence-evidence/trace_reach.py
```

It records test and harness calls with `sys.monitoring` (`PY_START`, `PY_RETURN`, `PY_UNWIND`) while `render_fixture_files()` runs, then disassembles the executed functions for the constants they load. A function is a seed helper when a call happens with `seed_acts`, `_complete_core_return`, or `render_fixture_files` on the stack, the caller is not a module body, and the file is not `tests/evidence_loader.py`.

The generator's own imports are the three entries:

| Import | Why it is reached |
| --- | --- |
| `base_return` | The complete current-core return, before this generator edits it. |
| `_finish` | Stamps the v70 package adoption, release checksum, and actor. |
| `_handover` | Hands the Social Security family over and reconfirms its closure. |

`base_return` calls `w2g._w2g_return([])`. That calls withholding `_base`, which calls the other-dependents `build`, which calls child-tax-credit `build_acts`, which calls `_senior_acts`, which calls the taxable-income probe `_base_acts`. `_base_acts` calls the SSA, unemployment, capital-gain, IRA, wash-sale, and Form 1099-K builders those returns already share. `_finish` loads the probe and calls mortgage `_load_fixture_adoption`. `_handover` calls the production Social Security handover, then the probe's `_act` and `_attested`.

## Source fixture

`source-fixture/complete-core-return.jsonl` is the act list `_complete_core_return()` returns, before `_replace_w2_identity` and the Box 1 edits. 294 lines, 324,079 bytes, synthetic `demo.*` ids. `source-fixture/generate.py` (246 lines) reads that file, applies the same edits as `seed_acts` and `render_fixture_files`, and imports no test module. `source-fixture/result.json` records the byte match.

Lines added: 294 of source plus 246 of generator. Tests touched: 0.

After Track 1 points the real generator at a source file, `tests/test_entry_loop_t1.py::test_v70_seed_regenerates_and_leaves_only_box1_open` fails when the committed source and the committed seed disagree. That is source-fixture drift. A later edit to a test helper leaves the regenerated bytes unchanged, so the same test stays green. Refreshing the source from the helpers is a deliberate step.

## Move

`build_move_package.py` reads `trace.json` and writes `move/seed_helpers/`. It copies the 51 top-level helper functions (nested functions stay inside them), the assignments those functions need, and the imports that bind those names. Imports of a moved module are rewritten to `seed_helpers`. `ROOT` and `REPO` walk parents until `packages/kernel` and `tests` are both present.

Two functions are replaced so the copy does not load a test file. `_probe` returns the copied probe module. `_sdd` returns the copied senior-deduction module. `_ssa_acts` imports the copied IRA module. One constant is inlined from the earned-income child tests, `EIC_CHILD_KIND = "tax.us.eic-child"`, because a copied assignment names it and that module is not otherwise on this seed's path.

`move/generate.py` (300 lines) calls `base_return`, `_finish`, and `_handover` from the copy and applies the same edits. An AST walk of the package and the generator finds no `tests` import. After the run, `sys.modules` has no `tests` module that the run introduced. `move/result.json` records the byte match.

Lines: 1,870 of helper-function source, in a package of 2,493 lines (the rest is the constants, imports, and path rewrite). Generator: 300 lines. A real move would edit the 18 helper modules, retarget the 56 other test modules, and retarget the 2 tools.

Some names in the copied functions are not defined, because this seed never calls them: `_with_taxable_interest` and `child_fid` in the child-tax-credit copy, `_introduce` and `_transition` in withholding and W-2G, `_rel_fid` and `child_fid` in the other-dependents copy, and `_close_w2_box1_and_box2` in the refund copy. Taking one of those branches would raise `NameError`. This regeneration does not take them.

After Track 1, the byte-regeneration test fails when the moved helper code and the committed seed disagree. That is helper drift. Edits that remain only in the old test-module copies leave the regenerated bytes unchanged. The test also stays green when the generator imports a test module and the bytes still match.

## Recommendation

Build the source fixture.

The seed's contract is the bytes of this return. The helper closure is 1,870 lines across 18 modules, and a move retargets 56 other test modules and 2 tools. The source fixture keeps that graph where it is and makes regeneration read a named synthetic file.

Track 1 file: `packages/sample_data/entry_loop_v70/complete-core-return.jsonl`, next to the seed. The plan allows a decision to name a non-runtime sample-data source. The prototype file stays under this evidence directory until that decision.

The check that fails if the generator imports a test module: parse the generator, and fail on `import tests` or `from tests`. Run it, and fail if `tests` or a `tests.*` module appears in `sys.modules`. The byte-regeneration test does not do either. Add that check in Track 1. Leave the byte test in place so source and seed cannot drift apart.

## Decisions for the foreman

1. Adopt the source fixture. The move also regenerates the seed byte for byte; its cost is the 2,493-line package and the 56 tests plus 2 tools.
2. Name `packages/sample_data/entry_loop_v70/complete-core-return.jsonl` as the Track 1 source. P0 did not write it there.
3. Add the import check beside the byte-regeneration test. The byte test then catches source-fixture drift. Helper drift becomes a deliberate source refresh.
4. Leave the other golden generators that import test modules out of this milestone. The plan already sets them aside.
5. Stop here. Track 1 is the first change under `packages/`, and only if decision 2 names that sample-data file.
