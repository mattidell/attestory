# P0: gains and break-even sales reach Schedule D

Charter: `docs/reviews/gain-break-even/charter-p0.md`. Plan:
`docs/phases/engine-breadth/milestones/gain-break-even.md`. Source: branch
`milestone/gain-break-even-2025` from `5430b843`, published core v96
(registry v94, release v94). No production, test or content file was edited.

## Result in one paragraph

A gain and an exact break-even reach Form 8949, Schedule D, Form 1040 line 7a
and the line 16 tax correctly on every sale path the engine accepts, short
and long term, single and married filing jointly. All 50 returns ran to
`saturated` with no blocked rule and no open question. All 1,134 checks match
the hand values from the 2025 instructions: Form 8949 part totals, Schedule D
lines 1a to 16, Form 1040 lines 7a, 15 and 16, the preferential base, and the
Qualified Dividends and Capital Gain Tax Worksheet lines on every net long-term
gain. The four code W probes confirm the one bound: a positive box 1g amount
on a gain or break-even row blocks (ADR-0062 Decision 2, mechanism ADR-0066).
The census shows why the milestone is still worth having: existing tests run
gains and break-evens through the coordinator only on cores v11 to v94, never
on the current v96, and the long-term no-Form-1099-B break-even has never run
at all. **Recommendation: tests only.** No content repair.

(comparison). Outputs: `runs.json`, `comparison.json`.

Every return is the harness wage return
(`sale-family-audit-evidence/audit_harness.py`, loaded by path under a unique
name): one W-2, wages 50,000, standard deduction, no qualified dividends, plus
the sales. Each return gives the honest answers a filer with only these sales
gives (`honest`, `honest_exception1`, the three other Schedule D boundaries,
no inbound carryover, Form 1099-B box 4 and box 7 "no" per statement), and
age and blindness false. Each runs once through `live_coordinate_run` on core
v96, and the saved page is rendered by the real `_render_page`; every line is
read from the model embedded in the saved page, asserted equal to the
presentation model. Wall time 30 s on 9 workers.

### Bounds found

- **ADR-0062 Decision 2** (accepted; mechanism replaced by ADR-0066's
  declarative member constraints): "block if (g > 0) AND (d >= e)", code W on
  a gain or break-even row
  (`docs/adr/0062-form8949-attachment-arithmetic-and-schedule-d-composition.md`
  line 77), carried as `CODE_W_ON_GAIN` on
  `packages/content/tax/2025/family.f1099b-covered-w-lt.v2.json` line 57 and
  its short-term sibling. All four probes block at
  `f1099b.covered-w-{st,lt}.member-validation.synthesized`
  (`DEPENDENCY_INVALID`, `CODE_W_ON_GAIN` and `ADJUSTMENT_EXCEEDS_LOSS`); line
  1b/8b, line 16, line 7a and line 16 tax are blocked, no question is asked,
  and the page shows both reasons on line 1b/8b. Correct by the instructions
  (a wash-sale disallowance only exists on a loss), so a code W gain is a row
  with box 1g of 0, which the engine accepts and computes.
- **Break-even reaches Schedule D by design.** A return whose only sale nets
  zero answers both Exception 1 questions literally "yes" (no gain other than
  box 2a, no loss), yet the engine still files Form 8949 and Schedule D with
  line 16 = 0: `rule.selected-preferential-base` v12 notes, "v10: any recorded
  sale ... is Schedule D activity, so a sale whose column (h) is zero ...
  reaches it" (`packages/content/tax/2025/rule.selected-preferential-base.v12.json`
  line 32), and `rule.form1040-line16` v9 line 23 (v7, the sale count selects
  the Schedule D route). This matches the line 7a rule that a filer who sold
  a capital asset completes Form 8949 and Schedule D; every dollar is the
  same either way.
- **Worksheet lines on a non-preferential return.** On short-term-only and
  break-even returns the worksheet lines still publish as intermediates
  (line 4 = 0), although the instructions say not to use the worksheet when
  line 15 or 16 is zero or less and there are no qualified dividends
  (i1040sd line 1079). Line 25 then equals line 24, the Tax Table on line 15,
  so line 16 is the table amount on every such return. No dollar differs;
  `rule.form1040-line16` v9's notes describe the branch.
- No 2026 carryover arises (no case ends in a net loss).

## Recommendation

**Tests only.** No content successor. Track 1 pins, through
`live_coordinate_run` and the saved page on core v96, at least:

- a gain and a break-even on each path and term (the 22 single-filer cases
  here, including the code W gain with box 1g 0 and the code W full
  disallowance break-even), with Schedule D lines 1a-16, Form 1040 lines 7a,
  15 and 16, and the Form 8949 part totals against these hand values;
- the never-run cell: no Form 1099-B, long-term, break-even;
- one joint-filer long-term gain (all gain at 0%) and the three mixed
  returns, single, for the worksheet and the loss-on-line-15 table path;
- one code W probe (box 1g on a gain) asserting the `CODE_W_ON_GAIN` block,
  so the ADR-0062 bound stays visible.

Since no content changes, the plan's full-surface replay is not needed.

## Decisions for the foreman

1. **Scope of Track 1.** Pin the full 50-return set, or the suggested subset
   above (27 returns, about 15 s on 9 workers). Recommended: the subset;
   the joint-filer variants add no new route.
2. **Break-even and Exception 1.** The engine files Schedule D for a sale
   that nets zero even when both Exception 1 answers are "yes". That is the
   ratified v10 rule and costs no dollar; Track 1 can pin it as is. Noted
   only, no change recommended.
3. **No question on a code W gain with box 1g.** The block explains itself on
   the page but asks nothing; out of this milestone's scope, noted only.
