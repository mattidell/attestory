# P0: age 65 and blindness are asked

Charter: `docs/reviews/age-blindness-asked/charter-p0.md`. Plan:
`docs/phases/engine-breadth/milestones/age-blindness-asked.md`. Measured on
published core v86 (registry v84, release v84), on question-wording's scratch
core v87 (registry v85, release v85) and on a scratch core v88 (registry v86,
release v86). `prototype.py` builds v87 by loading
`question-wording-evidence/prototype.py` and calling its `build`, then makes
v88 on top of it in the same scratch tree outside the repository.

Every case id below is in `probe-output.json`, every recorded list id in
`rerun-output.json`, every trace row in `trace.json`, and every quote in
`law.json`.

## Recommendation

Ask all four facts, and block the standard deduction, the age and
blindness amounts and the senior deduction until they are answered. It is a
content-only change: the four input bindings become `required`, four input
questions are added, and two readers get successors (worksheet line 1 v2,
Schedule 1-A line 36b v2). No engine, schema, expression operation,
selection or recording-surface change is needed, so no stop condition was
hit. The prototype is scratch core v88, built on question-wording's scratch
v87.

- **Probes.** All 11 cases reach their hand values on v86, v87 and v88
  once answered truthfully (33 runs). Unanswered, v86 and v87 publish the
  under-65, sighted amounts with no question; that is wrong in 7 of the 11
  cases. Unanswered on v88, 20 fields block and show only the new
  questions: the taxpayer's two on every return, and all four on a joint or
  separate return.
- **Recorded returns.** Of the 775 recorded lists question-wording replayed,
  691 compute on v86, and all 691 are newly asked: the taxpayer's two
  questions on each, since every one is a single return. The other 84 are
  refused identically on every run.
- **Answering restores every number.** Answered false, as each record
  implies, 690 of the 691 are identical to v86. The last one differs from
  v86 only in question-wording's own new sentence, and it is identical to
  v87.

One number changes on purpose. On a qualifying surviving spouse return,
v86 counts the spouse's boxes and the 2025 chart does not; no recorded
return has this (finding 1). The decisions are at the end.

## Trace (`trace.json`)

**Where the false comes from.** Two content declarations together, on v86
and v87 alike:

- The package binds each fact with `mode: optional_default`:
  `taxpayer_over_65`, `taxpayer_blind`, `spouse_over_65`, `spouse_blind`
  (`package.core-calculations.v86.json`, `input_bindings`).
- The fact type, declared in `core_calculations.vocabulary` (v2 on v86, the
  retitled v3 on v87), names `optional_default: parameter.default-false v1`,
  whose value is `false`.

The runner (`packages/derivation/runner.py`, the input-binding loop) publishes
the parameter's value as a `declared_default` finding for any
`optional_default` binding whose fact is not recorded. A `required` binding
gets no default: the symbol stays absent and every rule that requires it
blocks `DEPENDENCY_ABSENT` naming the symbol. The binding mode, not the fact
type, decides; a binding is package content. The fact types were introduced by
core Track 3 (`571f0cf8`); the bundle v2 that carries them now came with the v3
live-run inputs repair (`c5e35446`).

**Rules that read them.** Three member rules, the same on v86 and v87
(`readers`):

| Rule | Reads | How |
| --- | --- | --- |
| `dependents-worksheet-line-1` v1 | all four | Requires all four symbols. Counts the taxpayer's two boxes, and the spouse's two on a joint, separate or qualifying surviving spouse return. |
| `schedule1a-part-v-line-36a` v1 | `taxpayer_over_65` | Requires it. True, not separate, valid SSN yes: the line 35 amount; otherwise 0. |
| `schedule1a-part-v-line-36b` v1 | `spouse_over_65` | Requires it on every return. True, joint, spouse SSN yes: line 35; otherwise 0. |

`form1040-standard-deduction` v3 reads them only through worksheet line 1:
line 4b is line 1 times $2,000 (single, head of household) or $1,600, and
both the chart path (line 3 + 4b) and the dependent path (4c = 4a + 4b) add
it. No credit reads them. 61 rules consume these publications transitively
(`downstream_rule_count`), down to Form 1040 lines 12e, 13b, 14, 15, 16, 24,
33, 34 and 37, Schedule 8812 and Schedule 3.

**Presentation.** No form field shows a fact or line 1's count
(`form_fields_showing_a_fact_or_reader` is empty). Form 1040 line 12d's four
boxes are not a field of the package. Twenty fields show a downstream line
(`form_fields`), so a blocked fact blocks them.

**Who could supply them today.** No input question names any of the four on
v86 or v87 (`input_questions` is empty). No Python module under `packages/`
or `tools/` names them, so no recording surface writes them; an answer
enters as an ordinary assertion act of the fact type, which is how every
return-level answer enters. No committed act list under
`packages/sample_data/` records a value. Six test modules name them, on
their own cores, and the old symbol-input scenarios
(`tax/scenarios/standard_deduction_age_blind`) supply the symbols to the
pre-package runner. Neither is a filer-facing surface.

## Law (2025; `law.json`)

`law.py` fetched the 2025 Form 1040 instructions, Form 1040 and Publication
501 from irs.gov. The first two match question-wording `law.json`'s sha256.
Every quote's key phrases were found inside its line range.

- **Line 12d** (Form 1040, `form1040-line12d`; instructions 2183-2195,
  `age-65`): check a box for "You: Were born before January 2, 1961 / Are
  blind" and "Spouse: Was born before January 2, 1961 / Is blind" ... "if you
  are married and filing a joint return". "Don't check any boxes for your
  spouse if your filing status is head of household." question-wording's
  range for this quote (2183-2191) stops before that sentence; it is
  2193-2195.
- **Separate return** (2117-2127, `separate-return-spouse`): on a married
  filing separately return the spouse's boxes may be checked "if your spouse
  had no income, isn't filing a return, and can't be claimed as a dependent
  on another person's return". The chart footnote says the same (`chart`).
  Publication 501 says "no gross income" and omits "isn't filing"
  (`pub501-spouse`).
- **The day before the birthday and a 2025 death** (2128-2151,
  `death-2025`): "A person is considered to reach age 65 on the day before
  the person's 65th birthday." A spouse born February 14, 1960 who died
  February 13, 2025 is 65; one who died February 12, 2025 is not. For the
  taxpayer, line 12d points to Publication 501 (2152-2157); Publication 501
  (1984-1996, `pub501-death-of-taxpayer`): "consider the taxpayer to be 65 or
  older at the end of 2025 only if the taxpayer was 65 or older at the time
  of death."
- **Blindness** (2158-2179, `blindness`): totally blind as of December 31,
  2025, or an eye doctor's certified statement of 20/200 or worse in the
  better eye with glasses or contact lenses, or a field of 20 degrees or less.
  Publication 501: "blind on the last day of the year" (`pub501-blindness`).
  Neither says how blindness is judged for someone who died in 2025.
- **Amounts** (`chart`, 2319-2350): single 17,750 / 19,750; joint 33,100,
  34,700, 36,300, 37,900; qualifying surviving spouse 33,100 / 34,700 (two
  rows only: the spouse's boxes do not count); separate 17,350 to 22,150;
  head of household 25,625 / 27,625. Line 12e Exception 4 sends any checked
  box to the chart; Exception 1 sends a filer who can be claimed to the
  worksheet (`line12e-exceptions`).
- **Dependents worksheet** (2288-2313, `dependents-worksheet`): line 1 counts
  the same four boxes; line 4a is the smaller of earned income plus $450 and
  the base; 4b is line 1 times $1,600 ($2,000 single or head of household).
- **Senior deduction** (7876-7931, `senior-deduction`): born before January 2,
  1961, a valid SSN, $6,000 per person, a joint return for a married couple;
  a taxpayer who died in 2025 before reaching 65 does not qualify.

## Design (scratch core v88, `prototype-build.json`)

Six edits on top of v87, built with `tools/package_successor`
(`generate_to_directory`) and validated by it with no inherited
inconsistencies:

1. **Bindings.** The four input bindings change from `optional_default` to
   `required`. The fact types, their versions and the vocabulary bundle do
   not change; the bundle's `default-false` declaration stays, unused by
   this package (decision 4).
2. **Four questions** (`input-question.v1`, added as members and entry
   points, like every other input question):
   - `taxpayer-over-65`: "Were you born before January 2, 1961? A person
     reaches age 65 on the day before their 65th birthday, so a birthday of
     January 1, 1961 counts and January 2, 1961 does not. If this return is
     for someone who died in 2025 before reaching age 65, answer no."
   - `taxpayer-blind`: "Were you totally blind on December 31, 2025, or do
     you have a statement certified by your eye doctor (ophthalmologist or
     optometrist) that you can't see better than 20/200 in your better eye
     with glasses or contact lenses, or that your field of vision is 20
     degrees or less?"
   - `spouse-over-65`: "Was your spouse born before January 2, 1961? A person
     reaches age 65 on the day before their 65th birthday. If your spouse
     died in 2025 before reaching age 65, answer no. On a separate return,
     answer yes only if your spouse also had no income, isn't filing a
     return, and can't be claimed as a dependent on another person's
     return."
   - `spouse-blind`: "Was your spouse totally blind on December 31, 2025, or
     does your spouse have a statement certified by an eye doctor
     (ophthalmologist or optometrist) that they can't see better than 20/200
     in the better eye with glasses or contact lenses, or that their field
     of vision is 20 degrees or less?" and the same separate-return sentence.
3. **`dependents-worksheet-line-1` v2.** Requires only `filing_status`. An
   always-active `conditional_dependency_set` names the taxpayer's two facts,
   and on a joint or separate return all four, so every missing answer is
   asked in one round. The spouse's boxes count on a joint or separate
   return; v1 also counted them on a qualifying surviving spouse return
   (finding 1).
4. **`schedule1a-part-v-line-36b` v2.** Tests "married filing jointly" first
   and reads the spouse's age only then; every other return publishes 0
   without asking. The rest of v1's expression, including its valid-SSN
   set, is unchanged.

`schedule1a-part-v-line-36a` v1 already requires `taxpayer_over_65`, so it
blocks until answered; `form1040-standard-deduction` v3 and worksheet
lines 2 to 4c read the facts only through line 1. They are unchanged.

**Why this and not less.** A question alone does nothing while the default
holds: the presentation attaches an input question only to a
`DEPENDENCY_ABSENT` root, and a defaulted fact is never absent (v86 has no
question to show, and question-wording finding 2 measured that the titles
never reach the page). Changing the binding alone blocks a single return on
the spouse's facts, because v1 of both line 1 and line 36b requires them on
every return. So the binding, the questions and the two readers move
together.

**Stop conditions.** None hit. Everything is package content: a binding
mode, four `input-question.v1` citizens, and two `rule-artifact.v14`
successors using operations line 36a already uses (`choose`, `any`,
`categorical_compare`, `conditional_dependency_set`). No engine, schema,
expression operation, selection or recording-surface change. An answer is
an ordinary assertion of the fact type, as for every return-level question;
a boolean input question already exists (`f1098-scope-no-mortgage-statement`).
A real v88 needs the same keyed loader entries every core since v80 has
added (question-wording decision 5); the prototype lends v86's in memory.

## Findings outside the design

1. **Qualifying surviving spouse counted the spouse's boxes.** v86's
   worksheet line 1 counts spouse boxes on a qualifying surviving spouse
   return. The 2025 chart has only 1- and 2-box rows for that status, and
   line 12d's spouse boxes are for a joint (or qualifying separate) return.
   v88 drops it: `qss-spouse-born-1955` with spouse age recorded true gives
   12e 33,100 and line 16 1,693 on v86, and 31,500 and 1,853 on v88, which is
   the chart. Today the default false hides this. Asking the spouse on that
   status would have exposed it.
2. **The separate-return condition lives only in the question.** On a
   separate return the spouse's boxes count only if the spouse had no
   income, isn't filing and can't be claimed. v88 puts that condition in
   the two spouse questions. The v87 fact titles ("Spouse was born before
   January 2, 1961 ...") do not mention it, so on that status the recorded
   fact means more than its title says.
3. **Blindness at death is not stated.** The instructions and Publication
   501 quoted say "December 31, 2025" and "the last day of the year". They
   do not say how blindness is judged for a taxpayer or spouse who died in
   2025. The questions follow the instructions' words and add nothing.
4. **The recorded set has only single filers.** All 691 computing lists are
   single, and none states an age or blindness fact. Whether any is a
   dependent return was not measured. The joint, separate, head of household, qualifying
   surviving spouse and dependent behaviour rests on the 11 probes. Track 0
   should add joint and dependent recorded returns.
5. **Every live-core helper return will block.** `tests/helpers/current_core_returns.py`
   `base_return` and the 18 test files that name the helper, plus the harnesses
   the evidence scripts load, record none of the four facts. On a real v88
   they block at line 12e until they answer the taxpayer's two facts false
   (and the spouse's on joint helpers). This is test and helper work for
   Track 1, not content.
6. **Line 12d's boxes are not shown.** No form field shows the four boxes
   or line 1's count. The page shows the questions while they are open,
   and then only the amounts. This is unchanged here.
7. **question-wording `law.json` range.** Its `age-65` quote includes the
   head-of-household sentence, but its range (2183-2191) stops before it.
   That sentence is at 2193-2195. This `law.json` uses 2183-2195.

## Decisions for the foreman

1. **Take the design**: the four required bindings, the four questions,
   worksheet line 1 v2 and line 36b v2. This is recommended. It is content
   only, and it needs no engine change.
2. **Qualifying surviving spouse** (finding 1): count only the taxpayer's
   boxes, as the chart does. This is recommended. It is the one intended
   number change, and no recorded return has it. The alternative is to keep
   v1's count and ask a surviving spouse about the deceased spouse.
3. **Separate-return condition** (finding 2): either retitle the two spouse
   facts in the vocabulary bundle successor to carry the condition, or let
   the questions alone carry it. If question-wording's bundle v3 is taken
   anyway, the retitle is the same successor and costs nothing more, so it
   is recommended in that case.
4. **The unused default.** The fact types still declare `default-false`,
   though no binding uses it. Removing it means a fact-type v2 and a new pin
   in every reader. Leaving it is recommended; record that the binding mode
   decides.
5. **Question words**: confirm the four sentences, in particular "If this
   return is for someone who died in 2025 before reaching age 65, answer
   no" for the taxpayer (Publication 501) and the separate-return sentence
   on both spouse questions.
6. **Track 1 scope**: the loader entries for v88 (as for v87), and finding
   5's helper and test answers. Every test that runs a return on the new
   core must state the taxpayer's two facts.
7. **Track 0**: add joint, separate and dependent recorded returns to the
   rerun set (finding 4), and decide whether blindness at death (finding 3)
   is parked.
8. **Order**: v88 is built on question-wording's scratch v87. If the
   owner's disposition on PR #273 changes v87, rerun `prototype.py`, the
   probe and the rerun; none of this design depends on v87's words.
