Plan: `docs/phases/engine-breadth/milestones/statement-question-labels.md`.
On published core v106 (registry v104, release v104). Nothing under
`packages/` or `tests/` was edited; the design runs as an in-memory wrapper.

## Result in one paragraph

Three Form 1099-B questions are per statement on v106: the box 4 amount,
the box 4 yes/no, and box 7. Every other Form 1099-B question is per sale.
Today the box 4 amount and box 7 questions appear on blocked lines once per
line, with no statement named and no link, however many statements need
them. The box 4 yes/no question never appears as a reason on v106. Since
v83, line 25b asks only for the amount, and the amount's wording covers
"except a statement you said shows no...". The cause is in the engine
record. Both questions reach the page through a `require_paired` block
(line 25b for box 4, the per-family `box7-loss-check` rules for box 7).
That block names only the bare fact type, never the statement. Content
cannot fix this. A question citizen is static text, and the recorded label
belongs to the filer. The reason schema and the renderer already carry and
show `statementLabel` on a reason, so no schema successor is needed. The
smallest route is in the projection. When a reason is the input question of
a fact keyed on `statement`, recompute that row's `require_paired` from the
current facts and name the uncovered statements. Box 4 needs one more input.
Line 25b's pairing is gated and runs over every statement, so the recompute
alone would also name a statement the filer said shows nothing. The per-sale
`*.box4-amount-needed` results the engine publishes narrow it. On a scratch
build, all 18 synthetic cases show exactly the expected labels. The
775-list recorded replay passes 775 of 775. Of those, 141 lists change, and
only in question reasons. There are no number, disposition, code, report or
other model changes, and 0 semantic failures. **Recommendation: take the
projection route. In my reading it adds a presentation contract that later
content is written against (how a question is attributed to a statement),
the same tier as ADR 0087. A proposed ADR is drafted in `adr-draft.md`.
Stop for the owner before Track 1.**

The recorded corpus (`inventory-all.json`, 775 lists, 691 succeed, 84
`error/error` as in earlier P0s) has 141 lists that show a per-statement
question. 120 of them have one statement and 21 have two or more. That is
3,840 (question, line) pairs: 690 for the box 4 amount and 3,150 for box 7.
No line shows the sentence more than once. No question group exists for
these questions while they are unanswered, because a group needs an
existing fact. When a fact exists, `_question_group_catalog` already puts
`statementLabel` on its `answerTarget` (`presentation_projection.py:1223`).
Every recorded statement is labelled `Synthetic`, so the corpus alone
cannot show two statements told apart. The cases relabel them.

Where the label lives: the statement entity's recorded `label`
(`entity-introduced`, kind `tax.us.f1099b-statement`), read through
`state.fact_state.entities`, as `_statement_label` already does. The fact
id of the missing answer is not on the row. The statement must be
recovered.

## 2. Routes

| Route | Can it name the statement? | Cost |
| --- | --- | --- |
| Content (reword the question) | No. A question is static, and the label is the filer's | — |
| Content successor that makes line 25b block per sale | Partly. Box 7 already has per-sale rows; line 25b would still name the bare type through its pairing | A new rule shape on every sale return, with explanation-graph changes |
| Engine: `require_paired` records keyed fact ids in `missing` | Yes for box 7. For box 4 it would also name the statements that said "no" | Changes report rows for every blocked pairing (derivation contract) |
| **Projection, existing `statementLabel` reason field** | Yes, both, exactly (section 3) | Projection code and one tax-side table. No schema, content or core change |
| Schema successor (a question declaring its own scope) | Yes | New published schema and an ADR. Heavier than needed |

## 3. Design (scratch, `design.py`)

After the unchanged walk produces its reasons:

1. For a reason that is the input question of a fact type `F` with exactly
   one entity identity key, named `statement`, plus literal keys, collect
   the blocked rows the line reaches whose `missing` names `F` bare.
2. For each row, recompute every `require_paired` node of that row's rule
   whose `withholding` is `F`. The result is the `key` values of current
   income rows that no current `F` row covers. This is the same test
   `evaluator._require_paired` runs, applied to the same current rows.
3. Box 4 only (`NEED_SYMBOLS`): keep statements with a sale whose published
   `*.box4-amount-needed` value is above 0. Without this, the
   `two.box4-no-beside-yes` case would name the statement the filer said
   shows no withholding.
4. If every reached row yields at least one statement, and each has one
   current label, replace the reason in place with one reason per
   statement: `{"sentence", "statementLabel": {"statement", "taxYear"}}`.
   They are sorted by label then fact id, and identity is the fact id,
   never the label. Question-reference indices are remapped. Anything else
   leaves the reason as it is (fail closed to today's page).

A first run without the `statement`-key restriction labelled the Form 8949
no-1099-B per-sale basis and proceeds questions (keyed `sale`) with the
sale's label under `statementLabel.statement`. That is wrong, and the
semantic check caught it on 4 lists. The restriction is part of the design.

Renderer: unchanged. `citation-walk.v1.html:1459-1465` shows a reason with
`statementLabel` as a bold "label: " prefix. `check_page_dom.mjs`
(page-plain-words evidence) on three design pages: `section_errors` 0,
first-read leaks 0, and the text reads "demo statement 2: Enter the federal
income tax withheld in box 4 ...".

## 5. Replay

`replay.py` over `tools/recorded_replay.py` (strict `classify_full`, no
normalisation), published projection against the design, on v106 in one
shared run per list. Recorded lists ran in two parallel shards of five
workers, about 5 minutes. The expectations are confined to page records
under `resolved.reasons` and `resolved.questionRefs[].reasonIndices`. They
are broad by attribute, because a split moves later reasons one index. So
each list also passes `semantic_check` on the saved models. Report
dispositions must be equal. Every section's non-reason content must be
equal. The model outside sections must be equal. The design reasons, with
labelled per-statement runs folded back, must equal the published reasons
in order. Every question reference must name the same sentences.

| Set | Lists | Pass | Changed | Unexpected | Semantic failures | Lines labelled / labelled reasons |
| --- | --- | --- | --- | --- | --- | --- |
| recorded (`replay_summary.json`) | 775 | 775 (634 identical, 84 `error/error`) | 141, exactly the lists that show a question | 0 | 0 | 3,484 / 4,188 |
| cases (`replay_cases_summary.json`) | 18 | 18 | 15 | 0 | 0 | 260 / 416 |

3,484 lines equals the distinct lines behind the 3,840 (question, line)
pairs: a line carrying both questions counts once. Every line that showed a
question is labelled. One declared expectation (a moved `factId` /
`memberLabel`) was not used.

Controls (`replay_controls.json`): on three outputs, `semantic_check`
accepts the unmodified design and rejects each mutation. The mutations are
a dropped labelled reason, a label on another reason, a changed sentence,
and a moved question reference. Limit: dropping one of several labelled
reasons for the same sentence can fold back. The cases' expected labels,
not the replay, prove completeness.

## 6. What is not settled

- **Scope of the generic rule.** The recompute applies to any `statement`
  pairing. Line 25b also pairs Form 1099-INT, 1099-DIV, 1099-R, 1099-G box 4
  and SSA-1099 box 6 the same way, ungated, inside an `any` with a ref arm.
  The corpus reaches none of them. Track 1 either probes one (Form 1099-INT)
  or restricts the rule to Form 1099-B statements.
- **Where box 4's need lives.** In the scratch it is a table of eight
  symbols. Track 1 would put it in `packages/tax`, gated to core v106 or
  later, beside the collision labels. Or content could declare it (a schema
  successor).
- **One statement.** The design labels a single statement too: 120 of the
  141 changed lists. The plan's scope says "more than one".
- **Duplicate labels.** Two statements with one label show the same line
  twice. The broker label is reachable from the sale and could be added as
  `lender`.
- **Wording.** "demo statement 2: For each Form 1099-B ... is box 7 checked"
  reads awkwardly. Per-statement wording would be a content successor.
- **Silent lines.** A line that also waits on an unexplained cause stays
  silent, as today.
- **Form 8949 no-1099-B sales.** The per-sale questions (keyed `sale`) do
  not name the sale either. This is out of scope, and a candidate to park.
