## 3. Auditor reachability design

Every ID, enum, code, and pin remains reachable from the rendered DOM without
appearing in the caption a filer reads first:
1. **Status badges (lines & attachments):** keep existing CSS classes (`.badge.<disposition>`) and add `data-disposition="<raw>"` + `title="Recorded status: <raw>"`.
2. **Blocked banners (lines & attachments):** add `data-active-codes="<codes>"` and a collapsed `<details class="technical-details"><summary>Technical details</summary>...</details>` inside `.blocked-banner` carrying the exact `activeCodes`.
3. **Citation buttons:** keep `data-pin-id`, `data-pin-version`, `title="<pinId>@<pinVersion>"`, and the existing click-to-expand `.citation-detail` `<dl>` showing verbatim `<pinId>` and `<pinVersion>` under `Record ID` / `Record version`.
4. **Support trace (`renderShared`):** map known symbols to `field.label` via `MODEL.sections` (`field.binds_symbol`) with zero model change; keep `data-explanation-node`, `data-disposition-node`, `data-explanation-target`, `data-explanation-reuse`, plus `title` / `data-pin-id` / `data-dependency-symbol`; include a collapsed `<details class="audit-ids"><summary>Technical IDs</summary>...</details>` inside each expanded node carrying exact `symbol`, `id`, `version`, `produced_by.id`, and disposition `artifact_id` / `disposition`.
5. **Line 21 & mortgage detail panels:** move `Combined class`, raw parameter IDs, run ID / workspace revision, and finding IDs into collapsed `Technical details`; keep `calculationChain` as the explicitly labelled collapsed `Technical calculation record (for audit)`.

## 6. Risks and behavioural parsers

1. **`tools/sale_page_observation.py:739-758, 814-821` parses DOM text as a model-vs-DOM invariant.** It compares `.badge` innerText directly against `disposition.replace("_", " ")` (casefold) for every line and attachment, and compares `.line-value` against `"No value published — cannot compute."`. Changing badge or blocked-banner text without updating `tools/sale_page_observation.py` (and `tests/test_sale_page_observation.py`) breaks the real-Chrome sale-page observer. Reading `data-disposition` (or mapping via the same plain-label table) removes this fragility.
