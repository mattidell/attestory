## What core v83 reads

Full table: `box7-table.json`, written by `box7_table.py`.

The box 7 fact is `tax.us.2025.f1099b.statement-box7-loss-not-allowed` v1.
Identity keys are `statement` and `tax-year`. Values are `yes` and `no`.
The question `tax.us.2025.input-question.f1099b-statement-box7-loss-not-allowed` v1
is adopted on v83. Its text is unchanged in the recommended design:

> For each Form 1099-B or substitute statement you recorded a sale from, is box 7 ("If checked, loss is not allowed based on amount in 1d") checked for any sale on it?

One adopted rule reads the answer: `tax.us.2025.rule.schedule-d-line16` v3.
Its `when` is `require_paired` on the statement key, so a sale from an
unanswered statement blocks Schedule D line 16 and asks that question.
Its `value` blocks with `DEPENDENCY_ABSENT` and an empty missing list whenever
any of the eight sale counts is above zero and the box 7 answers are not all
`no`. A yes blocks the line even when every sale on that statement is a gain
or zero. The block publishes nothing, including a gain on the same return.

No loader presence pair reads this fact. The covered-flag refusal map has no
box 7 token. The pair for `f1099div.box7-foreign-tax-paid` is Form 1099-DIV box 7.

Form 1099-B, Copy B, box 7: "If checked, loss is not allowed based on amount in 1d."

Instructions for Recipient, Box 7: "If checked, you cannot take a loss on your tax return based on gross proceeds from a reportable change in control or capital structure reported in box 1d. See the Form 8949 and Schedule D (Form 1040) instructions. The broker should advise you of any losses on a separate statement."

Payer instructions: enter in box 1d the aggregate cash and the fair market value of property received, and check box 7. "Box 7. Check if Loss Not Allowed Based on Amount in Box 1d."

The 2025 Instructions for Form 8949 do not name box 7. Column (h): "Figure gain (or loss) on each row. First, subtract the cost or other basis in column (e) from the proceeds (sales price) in column (d). Then take into account any adjustments in column (g). Enter the gain (or loss) in column (h)." Certain nondeductible losses are sent to the Schedule D instructions.

Schedule D instructions, Example 2: proceeds $1,000, basis $5,000, box 7 checked, loss of $4,000 is not allowed. Enter code L in column (f) and $4,000 in column (g). Column (h) is -0- ($1,000 − $5,000 + $4,000).

Capital losses: deductible up to capital gains plus $3,000 ($1,500 if married filing separately). Schedule D Tax Worksheet, single 0% threshold: $48,350. The worksheet is not used when line 15 or line 16 is zero or less and there are no qualified dividends.

A loss for this test is column (h) strictly below zero after column (g). Exactly zero is not a loss. A wash that brings column (h) to zero is not a loss. The instructions tell the filer to report the sale with code L so column (h) is zero. This milestone does not compute that adjustment.

Hand constants for the probes: single filer, wages $50,000, withholding $4,500, standard deduction $15,750. Ordinary brackets are the adopted parameters: 10% to $11,925, 12% to $48,475, 22% to $103,350. Taxable income under $100,000 uses the Tax Table on the band midpoint, rounded half up. Line 7 is lines 1a + 1b + 2 + 3 plus the short-term carryover. Line 15 is lines 8a + 8b + 9 + 10 + 13 + 14. On this wage return, lines 3, 6, 10, 13, and 14 are zero. Line 16 is line 7 plus line 15. Line 21 is the positive loss allowed, at most $3,000. Line 7a is line 16 when line 16 is a gain or zero, and the negative of line 21 when line 16 is a loss. Preferential tax applies when line 15 and line 16 are both gains. The 0% band is $48,350.

## Design

`prototype.py` builds the scratch successor. `prototype-build.json` records 17 added members and 2 replacements. The question file is not replaced.

One new bundle, `tax.us.2025.f1099b.box7-sale-verdict.vocabulary` v1, holds a derived categorical fact `tax.us.2025.f1099b.box7-sale-verdict` v1 (`clear` or `disallowed`) and an inert boolean that is never recorded. Nothing asks the filer to record the verdict.

Eight subject rules, `tax.us.2025.rule.f1099b.{family}-txn.box7-verdict` v1, evaluate one sale at a time. The sale and the box 7 fact are both required, so an unanswered box 7 blocks that sale and names the fact. The verdict is `disallowed` when box 7 is `yes` and column (h) is strictly below zero. Every other joined sale publishes `clear`, including a gain, a zero, and a wash that brings column (h) to zero. Box 7 joins the sale on `statement` and `tax-year`, so a sale reads only its own statement.

Eight selection checks, `tax.us.2025.rule.f1099b.{family}-txn.box7-loss-check` v1, publish 0 when every sale in that family is `clear` and when the family is empty. They block with `DEPENDENCY_ABSENT` and an empty missing list when any sale is `disallowed`. Their `when` is `require_paired` of box 7 against that family's sales, so an unanswered statement asks the existing question before the verdicts are read as a failure.

`tax.us.2025.rule.schedule-d-line16` v4 still publishes line 7 plus line 15. It requires line 7, line 15, and the eight checks. It keeps the statement `require_paired` guard. It no longer treats any box 7 yes as a block, and it no longer requires the eight sale-count symbols.

The form field `tax.us.2025.schedule-d.line-16` v4 says line 16 equals line 7 plus line 15. The blocked explanation is:

> Schedule D line 16 has no value yet. It is waiting for line 7 or line 15. It is also blocked while a recorded Form 1099-B statement has no answer about box 7. It is blocked when box 7 is checked and a sale on that statement is at a loss: a loss based on the box 1d amount is not allowed, and this return does not compute it.

A gain and a loss on the same checked statement refuse the whole line 16. The gain is unpublished with the loss. A loss on a statement answered no is published, including when another statement is answered yes and has only gains.

## Recorded v83 returns on v84

`rerun.py` replayed the act lists in `tests/fixtures/f1099b_backup_withholding_v83/expected.json` with the recorded answers. `rerun-output.json` classifies 298 runs: 79 Track 0 cases, 213 returns, and 6 zero box-4 samples.

275 are identical, including every Track 0 case, every zero sample, and every return whose line 16 row already matched.

23 returns stay blocked and change one row. `rows.schedule-d-line16` drops the sale-count symbols from its missing list, because line 16 v4 does not require those counts. Lines, questions, reason sentences, and every other row stay equal. The count remains on the line 7 or line 15 row, which is what still blocks the return. None of the 23 publishes a value. None is a box 7 yes that now computes. The recorded corpus answered box 7 no, or had no sale that the old any-yes rule was refusing while the rest of the return computed.

The 23 ids and the dropped counts are in `rerun-output.json` under class `line16_missing_drops_sale_counts`.

## Recommendation

Adopt this content shape for core v84. The package successor validated. The twenty design probes match the hand on the scratch core. No engine change, schema change, expression operation, or recording-surface change was required.

Decisions for the foreman:

1. Refuse Schedule D line 16 when a checked statement has a column (h) below zero, rather than computing the Schedule D Example 2 code L adjustment that would publish column (h) as zero.
2. Keep asking the existing box 7 question for every statement that has a sale, including a statement whose sales are all gains or zero. Leave the question text as it is.
3. Let the form-field explanation be the sentence for a yes-plus-loss refusal. The measured block has an empty missing list, so no question is attached. Leave the covered-flag refusal map unchanged.
4. Refuse the whole of line 16 when one statement is checked and has both a gain and a loss. The loss is not published, and the gain on that statement is unpublished with it. A loss on a different statement, answered no, is published.
5. Whether line 16 v4 should also keep requiring the eight sale-count symbols. Keeping them would make the 23 already-blocked rows identical to v83. Dropping them, which is what the prototype does, leaves those returns blocked through line 7 or line 15 and changes only line 16's missing list.

Stop condition: none fired.
