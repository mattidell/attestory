guard value is false.

`packages/derivation/runner.py` lines 3041-3048 record a false guard preflight
as disposition `inapplicable` with `guard_result` false and no `missing`
names. The selection path does the same at lines 1326-1335. A declaring
`block` would have been recorded as blocked at lines 3057-3064. This guard
has no such block, so the symbol is inapplicable.

`packages/derivation/presentation_projection.py` `_closure_question_reasons`
attaches sentences only when every root the line reaches has a declared
question (docstring at lines 485-486). `reach` at lines 613-619 returns false

## Design

The preferred repair is the line 16 pattern. `prototype.py` writes
`rule.selected-preferential-base.v11.json` on schema `rule-artifact.v17`.
It leaves `value` unchanged. It rewrites only the `else` of the activity
`choose` whose `then` is true and whose `else` is
`schedule-d-required.conclusion` equal to `no`. That `else` becomes a
`choose`: when the conclusion is `no`, the arm stays true; otherwise the arm
is `{op: block, code: DEPENDENCY_ABSENT, missing: [the four line 16 names]}`.
The walk finds that node once. `generate_to_directory` accepts the body as
v17. No activity and a conclusion of no still publishes. Activity still takes
the outer `then`. No activity and a required Schedule D blocks with the four
names.

A projection change would teach `reach` to keep walking, or to keep sibling
questions, when a root is inapplicable. That changes the page for every
inapplicable producer, and it edits `packages/derivation/presentation_projection.py`,
which `milestone/blocked-sale-pages-2025` already has open. The content
successor makes this producer a blocked row whose roots are the four facts
that already have questions, so the published walk names them. The projection
change is the larger edit and is unnecessary.
