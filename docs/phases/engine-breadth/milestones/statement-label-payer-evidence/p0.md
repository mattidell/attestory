# P0 evidence — Recorded payer and broker labels on statement questions

## Per-form route on core v109

The same displayed statement label can belong to distinct statement
entities. The current question walk closes over fact identity, and its
order is recorded label followed by answer fact ID. Keep that attribution
and order. Add a second display string beside the exact statement label
when it identifies the statement among its peers.

| Existing question | Where the reported name lives | How the attributed question reaches it |
| --- | --- | --- |
| 1099-B box 4 amount | Current `tax.us.f1099b-broker` entity's `label` | The answer is keyed by `statement` and `tax-year`. Match those keys against the current sale findings pinned by the originating `require_paired` row. Those sales carry `broker`. The existing per-sale need table still determines which statements need an amount. |
| 1099-B box 7 | Same broker entity | Follow the matching current sale input on the originating box 7 pairing. The answer has the same statement/year shape. |
| 1099-INT box 4 | Current `tax.us.interest-payer` entity's `label` | The paired box 1, 3, 8 or 10 findings carry `payer`, copied into the exact answer identity by the existing line 25b walk. |
| 1099-DIV box 4 | Current `tax.us.dividend-payer` entity's `label` | The paired box 1a, 2a or 12 findings give the answer its `payer`. |
| IRA-family 1099-R box 4 | Current `tax.us.ira-payer` entity's `label` | The paired IRA box 1 taxable distribution gives the answer its `payer`. |
| 1099-G box 4 | Current `tax.us.unemployment-payer` entity's `label` | The paired box 1 unemployment finding gives the answer its `payer`. |
| SSA-1099 box 6 | No payer entity in this identity | Box 5 and the withholding answer use statement/year. Keep the existing statement-only display, including when labels repeat. |

Form 1099-B also has a `f1099b.statement-anchor` fact with a
`broker_name` value in the covered-long-term bundles. Where current, that
anchor can establish a peer's broker key. The positive two-sale fixture
has no anchor name and has all the keys needed on its sale findings and
entities. The anchor string can differ from the entity label and is
outside the existing blocked row's input. Prefer one display source,
the current entity label, for both boxes and for all supported forms.
The 1099-INT recording helper can store a descriptive prefix as part of
the entity label. This route displays the whole recorded label. Evidence
labels describe documents and may change on correction. Their text
has no reliable role in naming the party.

The relevant code is `_StatementQuestions.targets`, `_statement_reasons`
and `_validate_resolved` in
`packages/derivation/presentation_projection.py`, and the blocked-reason
rendering in `packages/presentation/pages/citation-walk.v1.html`. The
adopted line 25b v9 rule and the sale pairing rules declare the source
types. The per-form keys are listed in `scratch.py`. For production, keep
that eligibility tied to the tax-domain declaration and keep the reason
text observer in `tools/sale_page_observation.py` aligned with the page.

## Matching and fallbacks

Count distinct current statement entities of the same form and year
with current income or sale findings. A current 1099-B statement anchor
can establish a peer even without a sale. Count an answered peer, and
count several income findings or sales on one statement only once. An
entity introduction with no current source finding provides no peer
for this decision.

| Case | Scratch behavior |
| --- | --- |
| Exact duplicate statement labels and distinct recorded parties | Add the names in ADR 0089 order. For example, `demo Statement, demo Zulu Bank` followed by `demo Statement, demo Alpha Bank`, each beside the original question. |
| Only one duplicate statement still needs an answer | Add its name according to the same group, including the answered peer. |
| Different labels or labels that differ in case or spacing | Keep the existing reasons. The comparison of statement labels is exact. Spacing alone can be hard to see in the rendered page. |
| A party is missing, stale, ambiguous, of the wrong kind, or has a blank label | Keep the group's existing labels. No placeholder is added. |
| Equal payer names, or names that differ only in case or whitespace | Keep the group's existing labels. Compare payer names after case folding and collapsing whitespace. A displayed name uses the recorded string. |
| Same payer entity for multiple statements | Its single recorded display name cannot distinguish the statements. Use the same fallback as equal payer names on separate entities. |
| SSA-1099, repeated labels | Keep each statement-only reason. A payer name would have to come from another contract. |

## Scratch proof and trusted inputs

`scratch.py` loads the projection and page from the ratified merge
`f56d45ad450cc56f7d7559dbeed300ea27b3430e`. Both `origin/main` and
`HEAD` contain that commit. The overlay leaves the existing ADR 0089
question attribution and sort in place and changes only the display
reason construction, its validator, and the page prefix. The saved
model's v3 schema permits this reason field. The scratch activates only
on v109. The proposal conditions later eligibility on retaining the
same source contracts.

The controls in `probe.py` run inside real projection calls, using two
synthetic returns with duplicate labels and distinct recorded parties.
They modify copied projection inputs at the seam. Some corrupted inputs
would already be refused by ordinary admission. The replay in
`replay.py` takes admitted returns through the live coordinator and
checks the resulting model, report, and synthetic page render. The
trusted-input probe passed 26 checks on Form 1099-B and 20 on Form 1099-INT.

| Input the walk trusts | Removal or corruption control |
| --- | --- |
| Eligible core and the existing ADR 0089 attributed question | Disable the scratch gate. Remove the adopted rule. Modify the 1099-B row's block code or the 1099-INT row's missing type. Existing attribution refuses the missing rule and the two corrupt rows. The all-answered case verifies that a duplicate label cannot create a question. |
| Target's exact statement key and tax year | Remove the statement or year or substitute a different year. |
| Current statement entity, form kind, and exact nonblank label | Blank the target label. Change the peer's kind or label or supersede the peer. The synthetic replay also checks differently labelled statements and SSA-1099. |
| A current, same-year source finding for each peer | Mark the peer's source findings noncurrent while leaving the entity introduced, or move them to another tax year. The answered-peer cases verify eligibility uses the source, including when its question is absent. |
| The exact payer key already attributed for the four payer-keyed forms | Remove the key or substitute the peer's payer. |
| The current matching sale input and its broker key on each 1099-B attribution row | Remove or corrupt an input pin, mark the sale finding noncurrent, remove its broker key, or substitute the peer's broker. Change the sale value to confirm the party link uses identity keys. Remove the known publication inputs to exercise both the inherited box 4 need filter and the extra broker join. |
| Current payer or broker entity of the declared kind, with a usable display label | Supersede the party, change its kind, remove its label, or give it the same or a near-same name as its peer. Bind both sources to one party entity. A synthetic live case also records an all-whitespace payer label. |
| Existing saved reason position and field shape | The replay deletes one expected name, swaps distinct names, and adds a name to a distinct statement. Each mutation must fail the exact ordered comparison. |

The 1099-B replay exposed a v109 line 25b input pin that resolves to a
known publication and carries `origin: assertion`. The overlay recognizes
known publications by ID and leaves them outside the sale join. An
unresolved ordinary input pin closes the name path. This preserves the
existing ADR 0089 reason even when the extra display name cannot be proved.

The 84 admission errors do not provide a saved page for the second count.

For each saved list, the comparator requires the exact party string
at each expected reason index and no party strings elsewhere. It checks
the whole model and report after applying only those insertions to the
baseline. The full-surface helper can alias generated IDs when needed.
The run asserts the affected-list totals of zero and ten. The actual page
script produced the expected ordered prefixes beside the existing
question text in all 20 synthetic cases with a labelled question.
The all-answered case had no labelled question. The removed-name,
swapped-name, and spurious-name controls all failed the same exact
comparison. There were zero unexpected full-surface differences.

## Recommendation and decisions needed

Accept the proposed ADR 0089 amendment if the intended outcome is to
distinguish duplicate statements when the recorded names suffice. The
route runs in projection and the saved page, using current identity
keys and display labels. Track 1 depends on agreement about using the
entity label for 1099-B, exact matching for statement labels, and leaving
the whole group at its existing display when its party labels are
missing or visually equivalent. The foreman can then charter projection,
validation, rendering, and focused regression coverage. The prototype verifies
that generated reasons stay display-only. Track 1 should also reject
malformed models that link a payer-labelled reason to a question group.

A broader goal of distinguishing every duplicate would require another
identifying detail for SSA-1099, same-payer statements, or missing labels.
That choice belongs to the owner.
