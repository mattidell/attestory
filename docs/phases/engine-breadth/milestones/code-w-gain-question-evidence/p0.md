## Sources

The 2025 Instructions for Form 8949, 13 pages, created 20 January 2026,
SHA-256 `f077991c83b086810c46cbad3755e0f126cb8dfd88cf8bf8ab2d5605d6e7ab45`,
read from an ignored directory. Code W, "You have a nondeductible loss from
a wash sale":

> Report the sale or exchange on Form 8949 and enter the amount of the nondeductible loss as a positive number in column (g). See the Schedule D instructions for more information about wash sales generally and Pub. 550 for more information on wash sales involving substantially similar stock or securities. If you received a Form 1099-B or Form 1099-DA (or substitute statement) and the amount of nondeductible wash sale loss shown in box 1g on Form 1099-B or box 1i on Form 1099-DA is incorrect, enter the correct amount of the nondeductible loss as a positive number in column (g). If the amount of the nondeductible loss is less than the amount shown on Form 1099-B or Form 1099-DA (or substitute statement), attach a statement explaining the difference. If no part of the loss is a nondeductible loss from a wash sale transaction, enter -0- in column (g).

ADR-0062 Decision 2 (`docs/adr/0062-form8949-attachment-arithmetic-and-schedule-d-composition.md:71`) is two per-transaction guards. `guard_nonloss_adjustment` blocks when `g > 0` and `d >= e`: code W on a gain or a break-even. `guard_adjustment_exceeds_loss` blocks when `g > max(e - d, 0)`.

The filer's error on a code W gain is a positive wash-sale disallowance in
column (g) on a row that is not a loss. Box 1g is that amount as the broker
reported it. What they correct is the amount: the nondeductible wash-sale
loss, as a positive number, or 0 when no part of the loss is a wash-sale
nondeductible loss. On a gain or a break-even there is no loss to disallow,
so column (g) for code W is 0. The page already says why the row blocks. It
does not ask for that amount.

The fact the block reads is the sale's own adjustment. Covered families
read `box_1g_wash_sale_disallowed_amount` on the member
(`family.f1099b-covered-w-st.v2.json:67`). The scalar the filer supplied is
`f1099b.covered-w-st-txn.adjustment` (and the long-term twin). Noncovered
families read `wash_disallowed`. Proceeds and basis are the other two
inputs of the same test. A new fact would be a new answer.

## If content cannot

The smallest change that attaches a group and leaves family pins and the
valid loss alone is a projection change, at `explain`
(`presentation_projection.py:849`). When that function records a
`CODE_W_ON_GAIN` or `ADJUSTMENT_EXCEEDS_LOSS` meaning on a
`.member-validation.synthesized` row, the walk also records the input
question for the sale's own adjustment fact. Question refs
(`:1010`) and question groups (`:5634`) already link a fact type once the
walk has recorded it. The expression-block probe is that link, working, on
the wrong row.

There is no input question for the covered-w adjustment fact on v103. Adding
it is content, and route `input-question` shows it is not sufficient: the
walk has to record the fact type. The projection has no declared link from
a family-validation block code to that fact. ADR 0086 (`docs/adr/0086-block-declares-missing-names.md`)
lets an expression block declare missing names. This block is not an
expression. A projection link from these two codes to the adjustment fact
is a new routing contract. It needs an ADR. The owner writes it. This P0
does not build the projection change.

A schema change on the family constraint would be a new source-family
version and would unpin saved sale records. That is the larger change.

The missing list is born at `runner.py:1915`. Emitting the adjustment fact
type there would also let the existing walk attach the question. That is an
engine change with the same undeclared link, and the same need for an ADR.
The projection site is the smaller edit that creates the link without a
family successor and without changing when the row blocks.

## Decisions for the foreman

- Content cannot do this. The next step is the projection link at `presentation_projection.py:849`, and it needs an ADR the owner writes. Do not build it until then.
- The amount to correct is the existing adjustment (box 1g / column (g)), not a new fact. Covered and noncovered use different fields and different scalar fact types. One question has to reach all four families.
- `ADJUSTMENT_EXCEEDS_LOSS` fires beside `CODE_W_ON_GAIN` on every gain and break-even in this trace, because the loss floor is 0. A loss whose disallowance exceeds the loss, and only that guard, was not traced.
- The unconditional line block can attach the question and it also blocks a valid wash loss. That route is closed by the milestone non-goal.
- The EIC married-taxpayer root is out of scope.
- No replay. No package version is reserved. A later publication takes the next free version after `hoh-no-worksheet-ceilings`.
