# P0 — Link a question where the saved page already asks it

The baseline is the landed merge `5993ce933`, with core v109, registry
v107 and release v107. The evidence tools resolve the projector and page
from that commit after checking that it is an ancestor of `HEAD`. The
baseline does not depend on a remote branch name or a milestone working
commit.

## The route

Keep the typed answer links in `resolved.questionRefs` and
`questionGroups`. They require a canonical fact id, its declared keys,
and an applicable fact or family scope. A declaration of a question can
reach a line before a fact exists, or apply to several facts the line
cannot distinguish. Giving such a question a fabricated fact id or
linking to every catalogued answer would assert more than the walk found.

The scratch projection gives each otherwise unlinked asking reason a
`questionPrompt` fragment id. The fragment is based on its section id
and position in the final reason list. The saved page renders the
existing reason as a link, with the same wording and label. The
destination shows that same labelled question and the affected line.
The open reason object in presentation-model.v3 admits this additive
field. The runtime validator admits it on a blocked reason at its own
section and index, with no typed link on that index. The renderer uses
one stored id for the anchor and its destination. The question observer
can report these and typed links through one ordered reason traversal.

The projection takes the origin from the question walk's accepted
leaves. It carries member origins by subject keys, through selection
merging and final reason ordering. A statement or sale display copy
inherits provenance from the question that produced it. Existing
statement, payer, sale and roster wording stays visible. When a fixing
question sits alongside a plain explanation, the question carries the
link. The explanation keeps its own role.

The prototype uses one destination per displayed occurrence. Distinct
occurrences with the same wording or recorded name can stay distinct
without claiming that the labels identify an answer. A question with
zero or several possible answer facts gets its prompt destination with
no answer scope or answer status. Earlier saved v3 pages can be read
without the optional field.

| Form 1099-B box 4 amount | The adopted imperative question, with each statement label the existing ADR 0089 route proves. | The block pins, shared pairing result and published positive need can name the uncovered statements on eligible cores. The adopted question remains identifiable across earlier cores whose walk has only a bare type. |
| Other withholding or box 7 | The adopted input question, with its existing statement and payer or broker label when present. | The existing pairing can name complete answer keys on supported shapes, including payer when the fact type requires it. The label alone carries no identity. |
| Form 8949 sale | The adopted missing amount or fixing question with the existing sale label. | The existing pairing or same-family, same-code validation witness can identify the sale. A consistency reason still has no evidence of which amount disagrees. |
| No catalogued answer fact | The adopted family or fact question reached by the blocked walk. | A bare type or binding symbol can name the declaration but may provide no answer identity. A family closure would also need the applicable horizon identity. |
| Several or one unproven catalogued targets | The reached question itself. | Catalog presence or a matching sentence does not prove that the row named the answer. Existing exact fact or unique eligible scope links already carry the typed identity. |

## Comparison and trusted inputs

The saved model test enumerates the ordered question reason positions in
the ratified model using exact adopted wording, including imperative
questions. The scratch projector derives eligibility from the blocked
walk. Matching wording can describe more than one adopted declaration.
The destination uses the actual rendered occurrence so it never needs to
choose a producer by wording. Projection and validator use one fragment
identity function. The renderer uses the stored fragment for both ends
of the link and the DOM observation follows that fragment, checking its
visible question and label. Existing typed links keep their established
identity checks.

The replay calls the live coordinator once per list and runs both
projectors on the coordinator's inputs. The baseline projector receives
the original dispositions and the scratch output is saved through the
coordinator. The comparison asserts the ordered additions, strips only
those fields, then compares the complete typed saved model and report
rows. Setup and derivation failures precede projection and are shared
by construction. Their outcome census, exact case set and masked
failure details are checked independently.

| Witness | Corruption checked |
| --- | --- |
| Adopted question, exact fact-type pin and applicable closure family | Remove the question, change its fact pin, blank its sentence or remove the matching family from the grouped closure declaration. |
| Blocked predecessor and its leaf | Remove the row, make it published, change its code, change the missing symbol, empty the missing list or add an unexplained root. |
| Package input-binding map | Remove the binding needed to resolve the leaf to the adopted question. |
| Walk origin | Reuse the exact question wording as an unrelated constraint explanation. It remains plain. |
| Existing typed references and final reason positions | Move, remove or add a prompt marker, overwrite its destination, add one over a typed link or add one on an unchanged list. |
| Inherited sale labels and derived publications | Check a real validation finding against its publication act. Remove the act, change the act finding alone, or change the result finding alone. Reject the sale attribution on both the current and successor core. |
| Output and failures | Change wording, block code, model, report, outcome, failure class or failure message. Substitute the same setup error on both sides, and swap a save and error without changing the outcome counts. |

## Proposed ADR — A saved reason can link to the question without naming an answer fact

Status: **proposed**.

1. Every accepted asking occurrence in the saved page's blocked-line reasons
   carries a presentation link. Keep existing typed answer groups and scopes
   with their existing meaning.
2. Give an otherwise unlinked question an optional local fragment id in its
   reason. Retain the question's wording, display labels, order and existing
   typed indices. Derive eligibility from the existing authority that emitted
   the question. Do not infer it from punctuation, label equality or mere
   proximity to a matching declaration.
3. A prompt destination displays the question in the context of its affected
   line. It carries no claim about the presence, standing or identity of an
   answer. Use this destination if the reason carries display-only labels or
   the answer identity is absent, ambiguous or unproven. The saved page has no
   answer action.
4. Use the same fragment identity check for the projection and structural
   validator. Render the link and its destination from the stored id. Read
   asking reasons in display order through one link observer.
5. This is a presentation contract. All existing labels, explanations,
   calculations, dispositions, report rows, pins and published files retain
   their meaning.
