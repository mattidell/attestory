# P0: Form 1099-B backup withholding without a sale

Charter: `docs/reviews/f1099b-box4-only/charter-p0.md`.
Plan: `docs/phases/engine-breadth/milestones/f1099b-box4-only.md`.

Core v84 is package `core-calculations` v84, registry v82, release v82.
The prototype is a scratch core v85 (package v85, registry v83, release v83)
built outside the repository. No file under `packages/` was edited. No published
schema was edited. No new expression operation was required.

## What core v84 reads

Full table: `statement-table.json`, written by `statement_table.py`.

The box 4 amount is `tax.us.2025.f1099b.statement-box4-withholding` v1.
Identity keys are `statement` and `tax-year`. The value is a number ≥ 0.
It lives in bundle `tax.us.2025.f1099b.box4` v1. Source family
`tax.us.2025.f1099b.b4` v1 is adopted. Its closure claim says every current
amount is added to line 25b, including an amount whose statement has no sale,
and a return with no amount is asked nothing new. Line 25b v7 does not
`require_closed` that family. There is no closure-mapping for it.

Three adopted rules read the amount or the family:

| Rule on v84 | What it does |
| --- | --- |
| `rule.f1099b-b4-amount-symbol` v1 | Publishes 0 under the amount id so the subtotal selection can name it. The 0 is not the withholding. |
| `rule.f1099b-b4-withholding-subtotal` v1 | Selection: collect every current amount, or default 0 when none is recorded. |
| `rule.form1040-line25b` v7 | `require_paired` on the statement key between the eight sale types and the amount. Both value arms add the subtotal. |

The question that asks the amount is `input-question.f1099b-box4` v1:

> Enter the federal income tax withheld in box 4 of each Form 1099-B or substitute statement you recorded a sale from. If box 4 is blank, enter $0.

It is asked when `require_paired` needs an amount for a recorded sale's
statement. A recorded statement with no sale is not an income row, so the
question is not asked of it. The v82 yes/no question is still a package member
and is not read by line 25b v7.

Ten adopted rules pair on the statement key for Form 1099-B: line 25b v7,
Schedule D line 16 v4, and the eight box 7 loss checks. Those last nine read
box 7, not box 4.

**How a statement with no sale is recorded today.** There is no
`packages/tax/` recording module for Form 1099-B. A statement enters as a
kernel `entity-introduced` of kind `tax.us.f1099b-statement`. Recording a sale
introduces broker, statement, and transaction entities as the sale's identity.
A box 4 amount may be asserted on a statement that has no sale; line 25b
counts it (backup-withholding Decision 6). Nothing asks for that assertion.
The loader's v84 companion declaration copies v83: box 4 takes no presence
pair. The covered-flag refusal map is v83's map and has no box 4 token.

**What closes every Form 1099-B statement.** Nothing. Sale-family closures
close sales of each class. `f1099b.b4` is not closed. There is no
statement-set closure and no return-level question that asks whether every
Form 1099-B was recorded.

## Design

`prototype.py` builds the scratch successor. `prototype-build.json` records
3 added members and 2 replacements.

One new bundle, `tax.us.2025.f1099b.no-sale-box4` v1, holds two return-level
facts keyed only by tax year:

- `tax.us.2025.f1099b.no-sale-box4-present` v1, yes or no.
- `tax.us.2025.f1099b.no-sale-box4-withholding` v1, number ≥ 0.

Two questions target them. The per-statement box 4 question is unchanged.

`tax.us.2025.rule.form1040-line25b` v8 keeps the v7 pairing and the six
subtotals. Its `when` also requires the present fact to be yes or no. Its
value adds the return-level amount when present is yes, and 0 when present
is no. An unanswered present blocks before the amount is read. A yes with
no amount blocks naming the amount.

Form field `tax.us.2025.form1040.line-25b` v6 says line 25b is also blocked
while it is unanswered whether a Form 1099-B shows box 4 withholding and no
closed sale.

This is content only. A return-level amount needs no new statement recording
surface. A per-statement-only ask would need a way for the filer to record a
statement with no sale; that is a recording-surface change and was not taken.

The existing subtotal still collects every current per-statement amount,
including a no-sale one (Decision 6). If the filer also enters the same
dollars at return level, line 25b adds both (`no_sale_then_sale_added_double`
publishes 300). The honest answers keep one copy: either the return-level
amount with no per-statement amount (`b4_only_return_level`), or a
per-statement amount with return-level 0 (`b4_only_recorded`). After a sale
is added to that statement, present is no and the per-statement amount
counts once (`no_sale_then_sale_added`).

## Recommendation

Adopt this content shape for core v85. The package successor validated. The
thirteen design probes match the hand on the scratch core. No engine change,
schema change, expression operation, or recording-surface change was
required.

Decisions for the foreman:

1. Ask a return-level yes/no whether the filer received a Form 1099-B that
   shows box 4 withholding and no closed sale, rather than a per-statement
   question that would need a new recording surface.
2. Keep the existing per-statement box 4 question for statements that have a
   sale. Leave its text as it is.
3. When the return-level answer is yes, ask one return-level amount (the
   total of those statements) and add it to line 25b. When the answer is no,
   add nothing new and ask nothing more.
4. Accept that every return is asked the yes/no, including a return with no
   Form 1099-B. Answering no keeps the published numbers. A recorded v84
   return that already computes will newly block until that question is
   answered.
5. Keep Decision 6: a per-statement amount whose statement has no sale still
   counts. The filer must not also enter those dollars at return level. Track
   0 should pin the double-count (`no_sale_then_sale_added_double`) and the
   honest single-count paths.
6. After a sale is added to a previously no-sale statement, present is no
   and the per-statement amount remains the one copy. After a sale is
   removed, the leftover per-statement amount still counts; present yes with
   return-level 0 adds nothing extra.

Stop condition: none fired.
