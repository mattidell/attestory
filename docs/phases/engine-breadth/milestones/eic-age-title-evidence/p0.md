# P0: where the age fact's title is shown

Evidence for `docs/phases/engine-breadth/milestones/eic-age-title.md`.
Measured on published core v103 (registry v101, release v101) with a
probe script whose code and raw output were working artifacts and are not
kept. `wording.json` is the candidate title the scratch successor used.

The return is a synthetic single filer with wages of 7,000, no
qualifying child, and the other earned-income-credit answers recorded
yes. One run records `tax.us.2025.eic.age-25-under-65` as yes
(`demo.eat.age.answered`). One leaves it unanswered
(`demo.eat.age.unanswered`).

## Where it shows

The published title is the fact type title in
`packages/content/tax/2025/eic-questions.bundle.json` line 19, inside
`tax.us.2025.eic-questions.vocabulary` version v1. The fact type version
is v1. The title states the birth-date range and says that no means the
credit is $0. It does not state age at death.

The probe searched five places on both returns for that title's opening
sentence through "No means the credit is $0.": the presentation model,
the question groups inside it, the explanation graph, the disposition
report, and the saved page after its script block is removed. Every
search was empty. `title_shown_on_v103` is false.

What each surface does show:

- Question groups store the input question, copied verbatim.
  `packages/derivation/presentation_projection.py` lines 652–654 say
  every sentence is copied verbatim and is never replaced by a fact
  title. The group object at lines 1146–1150 is `id`, `question`,
  `answerTarget`, and `producers`. On the unanswered return the one age
  group has `factTypeId` `tax.us.2025.eic.age-25-under-65`,
  `factTypeVersion` v1, and a question that starts with the input
  question. The title is not in that question.
- The saved page is `packages/presentation/pages/citation-walk.v1.html`.
  Line 1208 requires the blocked reason's sentence to equal
  `group.question`. Line 1247 renders `group.question` as the card
  heading. `packages/derivation/live_session.py` lines 170–173 freeze
  the presentation model into a script on that page. The card text is
  that question. The title is not in the model the page freezes.
- The explanation graph's node is exactly `id`, `version`, `kind`,
  `symbol`, `value`, `produced_by`, and `edges`
  (`packages/derivation/explanation_graph.py` line 120). On the answered
  return the age fact contributes an input node whose value is `yes`,
  a derived node for `tax.us.2025.eic.answer.age-25-under-65` whose
  value is `1`, and a reference node. None of those nodes has a title.
  The unanswered return has no graph node for this fact.
- The disposition report is `run_id`, `stop_reason`, `dispositions`,
  `current`, `authorization_status`, and `authorization_grant_id`
  (`packages/derivation/live.py` lines 803–812). Both runs stop
  `saturated`. The title is not a report field.
- `factTypeTitle` is written for statement-amount source findings
  (`presentation_projection.py` lines 1836–1838) and for
  `unsupportedSourceFindings` (lines 5623–5631). This return's model
  has no calculation view and an empty unsupported-source list. The
  age group has no `sourceFindings`.

## Pins

The attested finding on the answered return is `demo.age-25-under-65`,
schema `finding.v2`, value `yes`, basis `attested`, fact id
`tax.us.2025.eic.age-25-under-65|tax-year=2025`. That fact id carries
the fact type id and the tax year. It does not carry a fact type
version. The finding's keys are `basis`, `evidence_ids`, `fact_id`,
`id`, `schema`, and `value`. It has no `pins` field. Human findings
are refused if they carry derivation pins
(`packages/kernel/findings.py` lines 757–761). The finding is current.

The act log adopts `tax.us.2025.eic-questions.vocabulary` version v1.
That adoption's fact type is version v1 and carries the published
title. The package adoption is `tax.us.2025.package.core-calculations`
version v103. The package names the bundle as an entrypoint
(`package.core-calculations.v103.json` lines 162–165) and as a
fact-type-bundle member (lines 3453–3458), both at version v1.

`rule.eic-answer.age-25-under-65.v4.json` lines 85–88 pin the fact type
by id and version v1 inside `category_literal`. The derived publication
pins the adopted package at v103 and that rule at v4.

`apply_bundle_adoption` (`packages/kernel/facts.py` lines 174–176)
replaces the fact type declaration when a revised bundle is adopted.
It does not rewrite findings. Supersession on this fact type is `free`
(`eic-questions.bundle.json` lines 16–18).

No other member body of core v103 contains the bundle id. The probe
indexed the v103 corpus and recorded `other_members_pinning_bundle`
as empty.

## What a successor does to the saved answer

The scratch candidate keeps the fact type id and version v1, writes
`eic-questions.bundle.v2.json` with the title in `wording.json`, and
replaces the package member and the one entrypoint. Byte-undo of that
wording edit restores the published bundle. `generate_to_directory`
accepted the candidate: core v104, registry v102, release v102.
`successor_build.status` is `valid`.

Three loads of the answered return:

1. The finished v103 log, replayed on the successor surface without a
   new finish. The kernel projection still has package v103, bundle v1,
   the published title, fact type version v1, and the yes finding
   current. The derivation refuses `REGISTRY_CHECKSUM_MISMATCH` with
   detail `registry bytes do not match the release attestation`. The
   saved release attestation does not describe the successor registry,
   so the run does not adopt the new title.
2. The same log opened (package adoption, Social Security
   family-handover, and that handover's reconfirm removed) and finished
   once on v104. Package pin v104. Bundle adoption still v1. Kernel
   title still the published title. Fact type version v1. The yes
   finding stays current, same id and fact id. Line 27a stays a
   published 537.
3. Those opened acts plus an adoption of bundle v2, then the same
   finish on v104. Package pin v104. Both bundle adoptions are present;
   the later one is v2 with the candidate title. Kernel title is the
   candidate title. Fact type version stays v1. The yes finding stays
   current, same id and fact id, still with no pins field. Line 27a
   stays a published 537. The title is still absent from the page, the
   question groups, the graph, and the report.

A later adoption of this bundle changes the kernel title and leaves
the saved yes and the credit amount in place. It does not change what
a filer or an auditor is shown.

> Rule 11—You Must Meet the Age Requirements. You must be at least age
> 25 but under age 65 at the end of 2025. If you are married filing a
> joint return, either you or your spouse must be at least age 25 but
> under age 65 at the end of 2025. It doesn’t matter which spouse meets
> the age test, as long as one of the spouses does.
>
> You meet the age test if you were born after December 31, 1960, and
> before January 2, 2001. If you are married filing a joint return, you
> meet the age test if either you or your spouse was born after
> December 31, 1960, and before January 2, 2001.

> Death of spouse. If you are filing a joint return with your spouse
> who died in 2025, you meet the age test if you are at least age 25
> but under age 65 at the end of 2025, or your spouse was at least age
> 25 but under age 65 at the time of death. Your spouse is considered
> to reach age 25 on the day before their 25th birthday. However, the
> rule for reaching age 65 is different; your spouse reaches age 65 on
> their 65th birthday.

> Example 1. You are married and filing a joint return with your spouse
> who died in August 2025. You are age 67. Your spouse would have
> become age 65 in November 2025. Because your spouse was under age 65
> at the time of death, you meet the age test.

> Death of taxpayer. A taxpayer who died in 2025 meets the age test if
> the taxpayer was at least age 25 but under age 65 at the time of
> death. A taxpayer is considered to reach age 25 on the day before the
> taxpayer’s 25th birthday. However, the rule for reaching age 65 is
> different; a taxpayer reaches age 65 on the taxpayer’s 65th birthday.

The input question already states that death rule. The fact type title
states only the birth-date range.

## Route

Park the title. It reaches none of the surfaces a filer or an auditor
reads, so a successor would not change what anyone sees. The scratch
successor is valid, and re-adopting it keeps the saved yes and line
27a, but the charter stops when the title is never shown.

The 775-list full-surface replay was not run. The charter runs that
replay for a content route.

## Decisions for the foreman

- Park this title. Leave Track 1 closed unless a later decision wants
  a title that current surfaces do not show.
- Leave the input question, `rule.eic-answer.age-25-under-65` v4, and
  the credit as they are. The question is what the blocked line and
  the question card show, and it already states age at death.
- If a later surface starts showing this fact type's title, the shape
  measured here is a new bundle version that keeps fact type id and
  version v1. Re-adopting that bundle kept the saved yes and line 27a
  at 537. Bumping the fact type version would move the rule's
  `category_literal` pin.
- A saved v103 log does not derive on the successor registry: the
  release attestation no longer matches those registry bytes. Moving
  the return onto the successor was a new package adoption, and that
  adoption kept the number.
- hoh-no-worksheet-ceilings may publish core v104. The scratch
  candidate used v104 only because it was the next free version on
  this branch. A later publication takes whatever version is free then.
