# P0: stopped, the reasons live in identity-bearing source families

Source `HEAD` `492ddacd`, branch `milestone/sale-reasons-plain-2025`.
Orientation matched Git. After fetch, the branch was zero behind and one
ahead of derived ratified line `origin/main`; no merged PR for the branch.
Charter: `docs/reviews/sale-reasons-plain/charter-p0.md`.

**Stopped under the charter's stop condition.** Both reasons are content,
but the content that carries them is a source-family declaration
(`member_constraints[].meaning`). A family's version is part of the
workspace's horizon-chain identity, and the sentence is copied into a
published finding value. A content successor therefore cannot change only
the sentences: on the scratch successor every one of the 700 successful
pairs lost publications and gained blocks. The smallest change that keeps
every number is a projection change (below). The census, drafts, scratch
successor, strict replay and mutation controls were all run so the foreman
can decide from evidence.

## Draft and source check

`wording.json` holds the draft, the same sentence in every family that
declares the code (the trace shows each family draws its own, so the
sentence need only be true for its own sales, but one sentence avoids a
term- or form-specific split):

- Holding period (all six families): "This sale is marked long-term but was
  entered with short-term sales, or marked short-term but entered with
  long-term sales; check the dates you acquired and sold it (more than 1 year
  is long-term) and, if you have a Form 1099-B, whether its box 2 shows
  short-term or long-term."
- Wash sale (covered-W short- and long-term): "The wash-sale loss disallowed
  in box 1g of this Form 1099-B is more than this sale's loss (its basis
  minus its proceeds, or zero if it is not a loss); check the box 1g amount
  against the proceeds in box 1d and the cost or other basis in box 1e."

Sources (local copies in an ignored directory, not committed): 2025 Instructions for Form
8949, SHA-256 `d3ddc2b91cf89087ca348ebb00dbd1c80bbc025fa4df1176753d25013f581a67`,
"Short-Term or Long-Term" (1 year or less is short-term; more than 1 year is
long-term; count from the day after acquisition; box 2 of Form 1099-B may
help determine the term) and the column (g) code W row (enter the
nondeductible wash-sale loss; box 1g shows it); 2025 Instructions for
Schedule D, SHA-256 `145b3d02ba6ce4257939dfbd8f99d519875224cb4ceb4237a1aa24ed862360f1`,
"Wash Sales" (a loss on the sale is disallowed). Truth per state: the
holding constraint fires only when `long_term` contradicts the family's term
(`"yes"` in short-term, `"no"` in long-term families), true for both ST and
LT; the "if you have a Form 1099-B" clause keeps it true for no-1099-B
sales. The wash constraint fires when box 1g exceeds
floor_zero(basis - proceeds), which the parenthesis states, including the
gain case; it reads only the sale's own fields, so it is true whether the
adjustment family is open or closed or its computation refuses. Neither
sentence is load-tested for page fit; the fresh review should still try to
falsify them.

## Strict replay

Both cores ran per list in nine workers (CPU count minus one), four
contiguous shards; **wall time 385.4 s** for 784 pairs. `srp_replay.py`
classifies with plain-line-texts `p0c_compare` gates, with the declared
successor versions, and with page-reason gates read against the v96 model
with only the declared sentences replaced.

Cause, from `replay.json`: in all 700 successful pairs a sale family is now
SOURCE_SET_UNCLOSED. Workspace horizon chains are keyed by family version
(`packages/kernel/horizons.py:63`) and closure authority reads only the
adopted version's chain (`packages/derivation/marshal.py:356`), so a v2/v3
family has no current horizon on existing records. 15,862 rows move from
published to SOURCE_SET_UNCLOSED and 34,472 to DEPENDENCY_ABSENT; 51,095
publications disappear; no shared publication changes value; no successor
page draws a new sentence (the validation that would draw it never runs).

Separately, the sentence is published data: the member validation copies
`meaning` into its finding value and content-addressed id
(`packages/derivation/runner.py:1825`). All 16 drawing lists carry an old
reason in a v96 publication value, so even a migrated successor changes
values on exactly the lists the milestone targets.

## Mutation controls

No scratch pair is admissible, so `srp_summarize.py` runs the controls on an
ideal successor of the first recorded drawing list (v96 rows and model with
only the declared sentences replaced). The classifier admits it as
expected sentences, then rejects all **15** mutations: publication value,
page value, boolean for number, disposition, refusal code, missing name,
question identity, unplanned sentence, planned sentence in the wrong
property, added/removed row, added/removed page field, old reason kept, and
the other reason's new sentence in its place (`mutations.json`).

## Recommendation and decisions for the foreman

Do not proceed to Track 1 on content successors. Smallest changes, in
order:

1. **Projection change (smallest that keeps every number).** Let the page
   reason for a member-validation block code come from a declared filer
   sentence held in a citizen that carries no horizon identity, and keep the
   family `meaning` as the engine's record. Touch point:
   `meaning_for`/`explain` in `presentation_projection.py:549-605`. It needs a
   home for the sentence: a new property on an existing wording citizen
   (a new schema version) or a new small citizen schema keyed by family and
   block code. Engine plus schema; no kernel or page change. Values,
   dispositions, codes and questions stay byte-identical; only page reasons
   change. The drafts above carry over unchanged.
2. **Family successors with migration.** The 73-citizen cascade plus, in
   every workspace holding a sale-family horizon (14 families), an ADR-0079
   `family-handover` act and re-confirmed closure answers. Changes the
   validation finding values and ids on the drawing lists and re-asks closure
   questions; it breaks the plan's "keeps its values and questions" goal.

Decisions:

- Choose route 1 (re-charter as an engine and schema milestone, or fold it
  into blocked-sale-pages, which already owns the saved sale page), route 2,
  or park.
- Whether the covered-W CODE_W_ON_GAIN meaning (drawn, still names block
  codes and "member") joins the scope; route 1 covers it at no extra cost.
- The two drafts are ready for adversarial review whichever route is chosen.

No packages/, tests/ or content edits; no governance reads, push or spawn;
no background jobs. Scratch cores and complete models stay outside the
repository.
