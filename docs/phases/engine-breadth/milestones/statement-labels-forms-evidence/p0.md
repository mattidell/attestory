# P0 — Statement labels on Form 1040 line 25b

The five withholding questions can name their statements in the projection.
The engine already checks each statement's answer on core v109. SSA-1099 fits
ADR 0089's existing answer identity. The four other forms need the identity
check to admit their declared payer key along with the statement and year.

## Inventory and route

Each form has one adopted input question with a `statement` identity key.
The scan matched adopted `input-question.v1` citizens by fact type and version
against the statement-keyed fact declarations. The table names the answer
types without the `tax.us.2025.` prefix. The version of
`rule.form1040-line25b` adopted by core v109 is v9.

| Form | Existing question | Income rows in the pairing | Full answer identity | Route |
| --- | --- | --- | --- | --- |
| 1099-INT | Box 4 withholding, `f1099int.box4-withholding` | Boxes 1, 3, 8, 10 | payer, statement, tax-year | Extend identity check for this type. Reuse the pairing. |
| 1099-DIV | Box 4 withholding, `f1099div.box4-withholding` | Boxes 1a, 2a, 12 | payer, statement, tax-year | Extend identity check for this type. Reuse the pairing. |

| 1099-G | Box 4 withholding, `f1099g.box4-withholding` | Unemployment compensation, box 1 | payer, statement, tax-year | Extend identity check for this type. Reuse the pairing. |
| SSA-1099 | Voluntary withholding in box 6, `ssa1099.box6-voluntary-withholding` | Net benefits, box 5 | statement, tax-year | Admit this statement kind and reuse ADR 0089's attribution. |

The existing box 4 sentence asks for federal income tax withheld on each
form, and says to enter $0 if the box is blank. The SSA-1099 sentence asks
for voluntary federal income tax withheld in box 6 and gives the same $0
instruction. The saved reasons preserve the exact adopted sentences.

When a pairing blocks, the line 25b disposition row reports
`DEPENDENCY_ABSENT` and the bare answer type. The same question reaches
lines 25b, 25d, 33, 34, 35a and 37 in the synthetic cases. There is one
unlabelled reason per reached line, including when two statements both need
an answer. Some carry a question link, as described below. No other
statement-keyed question for the five forms appeared. Income-family and
withholding-family closure asks use their own targets.

Each linked case has an existing group in the saved model. The renderer
uses the reason's index to show “See the question and affected lines above”
in place of the reason sentence. Splitting that reason before references
are assigned would link the labelled reasons to the existing answer card
and hide their labels. The scratch projection assigns the existing refs
first. It keeps the linked reason and inserts the display-only copies just
after it. It replaces an unlinked reason in place. If an existing
reference's index moves, it still points to the same sentence and group
with the same scopes. A group can refer to an already recorded answer, so
its existence is insufficient to identify an uncovered statement.

### Withholding keyed join

The earlier count check could be satisfied by an answer on an unrelated
statement. Core v109 already uses the `statement` join introduced by ADR
0083. The INT offset probe has one answered income statement, one
unanswered income statement and one withholding-only statement. Its line
25b still blocks and the scratch page names **demo Alpha**, the unanswered
income statement. The zero-answer probe confirms a $0 row covers only its
own statement. The report and withholding totals use the same evaluation
on either projection.

The existing closures decide whether the pairing runs. Once it runs,
every statement covered by the income input list needs a withholding
row. There is no narrower per-statement need, so all five reuse
`paired_coverage` with no new `STATEMENT_QUESTION_NEEDS` entry. The
blocked row's input pins constrain attribution to the findings the rule
actually read. An unclosed withholding family produces its existing
closure ask. The line 25b check remains within the listed income boxes
and its existing short-circuit order. A statement introduced on its own
or recorded solely through a box outside the pairing creates no label.
W-2 box 2 already pairs on `w2-slip` on line 25a and is outside this
amendment.

## Scratch proof and replay

[replay.py](replay.py) loads the baseline projection directly from
`c1d060d738cc83ab59adc0981092c0358bfcea50`, the landed PR #317 merge on
main and the milestone's starting point. It generates an in-memory
projection from that same Git blob for the scratch side. The existing
closure walk and `_StatementQuestions.targets` still do attribution,
including calling the evaluator's `paired_coverage`. The overlay is
limited to the five adopted types on v109. It admits their exact declared
identities and carries the statement and tax year to the saved reason.
It keeps payer in the answer identity and omits it from the display
payload. The Form 1099-B rules, gate and declared need stay on their
existing path. Focused v108 runs for INT and SSA compared equal saved
outputs with the v109 overlay inactive.

The comparator independently looks at the baseline line 25b block, the
actual current input findings it pinned, the five declared income sets and
the current entity labels. It constructs the exact expected reason list
for each section, including position, sentence, full label object and
duplicates. It uses the hand-written order in the synthetic matrix as
a second assertion. It also compares the count derived from actual saved
labels to the expected counts. The whole expected saved model and
report must match the scratch output. Existing unlabelled reasons,
numbers, dispositions, block codes, question targets, pins, and every
report row compare in the same pass. Failed saves compare outcome,
error class and path-masked message through the full-surface replay tool.

The executable controls remove a required label, reverse two distinct
labelled reasons and inject a labelled withholding ask on the unclosed
family's line 25b. The same full-surface comparator rejects all three.
The production saved page's script is exercised through the DOM checker on
line 25b for two missing answers per form and the three-statement INT
case with a $0 answer. Focused DOM checks on the single-statement INT
and SSA cases also show their labels beside their preserved links.
The full comparison uses fresh shards and no checkpoint inputs.
Run from the repository root with Node available for the DOM checks and
an output path in `REPLAY_SUMMARY`.

```sh
python3 docs/phases/engine-breadth/milestones/statement-labels-forms-evidence/replay.py \
  --workers 9 --out "$REPLAY_SUMMARY"
```

## Recommendation and decisions

- **Owner** — Accept the [proposed ADR 0089 amendment](adr-draft.md)
  before Track 1, including retaining an existing link and giving it
  adjacent display-only statement reasons. Adopt the five-fact scope and
  preserve duplicate labels as separate reasons in label and fact-id order.
- **Foreman** — Charter a projection-only implementation with a separate
  eligibility gate from v109 for the five facts. Keep the admitted
  `statement` and `payer` combinations explicit and require every answer
  key before expanding a question. Reuse the exact replay and the synthetic
  matrix for the built path. Close the roadmap's line 25b naming item
  within the five-form boundary.
