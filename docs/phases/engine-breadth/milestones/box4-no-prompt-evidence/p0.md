# P0: a box 4 no without an amount

## Result and evidence ceiling

Content alone can remove the per-statement amount requirement after a
statement-level no. The final scratch core v94 computes lines 25b and
25d and removes the amount prompt on that answer. Yes and unanswered
still need an amount when none is recorded. Explicit amounts retain their
published treatment, including a contradictory no with a positive amount.
No new JSON Schema version, engine, projection, page or kernel change is
needed by this prototype. Nothing under packages/ or tests/ was edited.

This is P0 executable evidence, not production content or independent
review. The final prototype uses existing schemas and passes the real
package-successor validator with no inherited inconsistencies. The
foreman still dispositions the design and charters Track 0.

The Orientation Block matched Git. Branch milestone/box4-no-prompt-2025
was 0 behind and 1 ahead of the derived ratified line origin/main
(`258afd0e`); no merged PR was found. Baseline is published core v93,

## Published wording and source meaning

The published yes/no is:

> For each Form 1099-B or substitute statement you recorded a sale from, does it show federal income tax withheld in box 4?

Source: packages/content/tax/2025/input-question.f1099b-statement-box4-withholding-reported.json:10.
It records f1099b.statement-box4-withholding-reported, keyed by statement
and tax year. The published amount prompt is:

> Enter the federal income tax withheld in box 4 of each Form 1099-B or substitute statement you recorded a sale from. If box 4 is blank, enter $0.

Source: packages/content/tax/2025/input-question.f1099b-box4.v1.json:10.
It records f1099b.statement-box4-withholding, a different fact.

A truthful no means there is no reported federal withholding to carry
from that statement: zero for that statement's contribution to line 25b.
It is not an absence declaration about other statements, a determination
that an incorrect form is correct, or a substitute for the separate
return-level question.

`source_audit.py` checked the local 2025 IRS PDFs; `law.json` records their
filenames, exact hashes, headings, PDF pages and the inference limit.
The PDFs were fetched from the official year-specific IRS sources and
validated as PDFs before extraction. Their hashes match the earlier
f1099b-backup-withholding source identities.

- 2025 Form 1040 instructions, PDF page 39, Line 25b—Form(s) 1099:
  “include the amount withheld.” The surrounding instruction puts
  withholding shown on Forms 1099 into line 25b.
  [IRS source](https://www.irs.gov/pub/irs-prior/i1040gi--2025.pdf).
- 2025 Form 1099-B instructions, PDF page 12, Box 4:
  “Enter backup withholding.” This is the reported withholding amount.
  [IRS source](https://www.irs.gov/pub/irs-prior/i1099b--2025.pdf).
- 2025 Form 1099-B recipient instructions, PDF page 7, Box 4:
  “Shows backup withholding.” The recipient is directed to include that
  amount as tax withheld.
  [IRS source](https://www.irs.gov/pub/irs-prior/f1099b--2025.pdf).

No new filer-facing sentence is proposed. The two question citizens,
their answer semantics and every form-field sentence remain unchanged.
The local source audit therefore checks the zero inference rather than
inventing a new question or changing any answer's tax meaning.

## Design comparison and selected scratch content

The repair changes the requirement, not the recorded amount or its sum.
For each of the eight sale subject types, a count rule reads existing
amount-row keys by statement. A second rule returns 0 when an amount
exists; otherwise it checks that statement's reported-answer rows and
returns 0 only for no, or 1 for yes/unanswered. The existing joined-key
mechanism keeps one statement's answer from satisfying another's.
A return-level selection reads every subject result and sums the need
flags. Zero is a guard result, not a fabricated amount assertion.

Line 25b v9 replaces only the sale pairing expression with:

```text
if the per-sale need count is zero:
    the sale amount requirement is satisfied
else:
    evaluate the original require_paired expression unchanged
```

All original count requirements, non-1099-B guards, rounding, subtotal
arithmetic and the return-level branch stay intact. The actual amount
subtotal still counts each statement amount once; it is never replaced
by a sum of per-sale withholding amounts, which could duplicate a
statement's withholding when it has several sales. The prototype adds
17 rules, one vocabulary bundle, and one line-25b successor. It uses
already-admitted rule-artifact schemas; it writes no schema file.

| Alternative | Cost and outcome |
| --- | --- |
| Selected per-sale guard with the original pairing fallback | Content only; statement-local answers, mixed statements, explicit amounts and original refusal codes preserved. Seventeen helper rules are the content cost. |
| Ask for explicit zero as today | No edits, but keeps the duplicate input and fails the desired no outcome. |
| Skip all pairing if any statement says no | Small expression, but one statement can hide another statement's unanswered amount. Rejected. |
| Pair every sale only with the yes/no | Still has to distinguish yes from no and obtain actual positive amounts; alone it cannot handle yes or preserve unanswered-with-amount. Rejected. |
| Publish a raw amount from no, or total per-sale effective amounts | Adds competing amount publications or risks summing one statement amount once per sale. The selected design changes neither amount identity nor the established subtotal. |
| Add a combined conditional-pair operator | Could reduce content, but requires engine and probably expression-schema work. Not needed by the executable content design; outside this charter. |
| Change projection/page prompt filtering | Does not fix the blocked payment line; overlaps blocked-sale-pages. Rejected. |

**Contradiction policy:** prefer an explicit amount. A recorded no with
200 remains 200, exactly as on v93; no is used only when its statement has
no amount. This preserves existing recorded amounts and avoids silently
dropping a tax payment. Refusing the contradiction instead would expand
the changed class beyond no-without-amount and is a foreman decision,
not a hidden prototype change. No refusal code was changed.

The compact first attempt could not put shared_key_count repeatedly or
in when: packages/derivation/package_validation.py:869 requires exactly
one occurrence in value. Separating the counts uses the admitted
mechanism. Two executable routing attempts also taught an important
boundary: a blocked helper changed 412 pins; moving a declaring block
into line 25b still changed 14 unresolved-family lists by overriding the
missing count with an early amount prompt. The final original-pairing
fallback preserves that count/closure behavior. The two discarded
comparisons are summarized in first-rerun-output.json and
second-rerun-output.json; neither is recommended for implementation.

The replay tool calls the 271 changes numbers_changed because its numeric

25b's missing list moving from statement-box4-withholding to

The 84 errors are established by this direct v93/v94 comparison, not
assumed to predate the work.

The plan's expected numerical unblocking is not what these 775 older
lists show: their separate return-level question remains unanswered.
No answer was added to manufacture a completed return. Removing one
requirement truthfully reveals that next question. The three named
recorded examples in the focused matrix already answer it and do show
25b/25d computing. They are not among the 775 default replay keys.
The original expected-change wording must retain this distinction;
defaulting the return-level answer would cross the parked boundary.

## Recommendation and decisions for the foreman

Proceed to Track 0 on the final content design, retaining the original
pairing fallback and the saved replay. Content has demonstrated the
needed boundary; an engine, schema, projection or page charter is not
warranted by this P0.

- Adopt explicit-amount precedence for no plus a positive amount, or
  separately disposition a refusal policy and its larger regression class.
- Accept the content cost of 17 helper rules, or have Track 0 challenge
  a smaller admitted content shape without weakening statement locality.
- Treat the 271 next-question changes as expected partial-return behavior.
  Keep the existing return-level question and total parked; do not default
  them to make the older corpus compute.
- Reuse the 775-list part and the three named recorded examples. Close
  mixed-statement isolation, repeated sales on one statement, correction/
  withdrawal, and the eight subject types independently before building.
- Keep statement naming and repeated shared page questions with
  blocked-sale-pages. This prototype needs no overlapping file edit.
