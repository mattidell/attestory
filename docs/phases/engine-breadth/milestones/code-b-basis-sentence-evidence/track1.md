## 1. Wording

`wording.py` writes `wording.json`: one row per citizen with the v2 text,
the v3 text and the 2025 instruction sections. The four citizens are the
code B short-term and long-term `ADJUSTMENT_EXCEEDS_LOSS` and
`CODE_W_ON_GAIN` explanations. The first sentence of each is kept. The
second becomes the Decision 1 sentence: "Check the proceeds and wash-sale
loss you entered against box 1d and box 1g of your Form 1099-B, and the
correct basis you entered against your own records, then fix whichever
amount is wrong."

## 2. Publication

`build.py --publish` imports the literal replacement and pin search from
the sale-explanation-wording `build.py`. It writes four v3 successors, each
with a byte-undo proof. It checks that no other v107 member pins any of the
four, so the closure has one level. `tools.package_successor` then
generates and validates `package.core-calculations.v108.json`,
`published-packages.v106.json` and
`demo.release.sli-worksheet-integration.2025.v106.json` (`build.json`).
The committed bytes are the generated bytes, and two builds gave the same
digests. Each of the four members and entrypoints is replaced in place.
The registry is add-only, with four citizens and one package appended. The
release differs from v105 only in its version and registry digest.
`packages/tax/loader.py` carries v107's covered-flag map and companion
declaration to v108. The rank-based switches already include v108.
`tests/test_noncovered_sales_v78_switch.py` is re-pinned to v79 through
v108.

## 3. Replay (`replay.py`; raw report not kept)

`replay.py` reuses sale-explanation-wording's `PlainWordsCompare`
unchanged, with this track's four sentences and its version moves (the four
explanations v2 to v3, core v107 to v108). It compares v107 against
published v108 on all 775 recorded lists in one shared
`recorded_replay.replay` process pool with nine workers, in 350 s:

- 775 lists, 775 passing, 0 failing, 0 unexpected differences;
- 691 expected changes and 84 identical, the lists that fail the same way
  on both cores;
- outcomes unchanged (691 success/success, 84 error/error);
- no number, disposition, block code or question target changed. The only
  raw differences are versions and 320 page sentences.

Both new sentences are reached: 320 replacements in 8 lists (the
`ADJUSTMENT_EXCEEDS_LOSS` sentence in 8 lists, the `CODE_W_ON_GAIN`
sentence in 2). No line had its reasons reordered. One of the five version
expectations was used, the package. Explanation citizen versions are not
saved in any output.

Controls (`controls-v108.json`, `replay.py --controls --keys <the two
lists in that file>`). On both lists the real comparison passes. It fails
when every new sentence has " X" appended (64 and 32 unexpected) and when
nothing is substituted (64 and 32 unexpected).

- `tests/test_code_b_basis_sentence_v108_package.py` (fast). The wording
  record is the four citizens, first sentence kept and second the Decision
  1 sentence. v108 replaces exactly the four members and entrypoints, in
  place, and nothing else in the package moves. Each successor is its
  predecessor plus the new sentence and v3. The registry is add-only, the
  release moves only its version and registry digest, and the loader
  carries v107. The v107 wording bar holds for every sentence v108 adopts,
  with the Decision 2 exception: the four use "basis" twice, each time as
  "the correct basis you entered".
- `tests/test_code_b_basis_sentence_v108_live.py` (live). v108 passes full
  `validate_package`. The ten code B synthetic cases (short-term and
  long-term: a valid loss and four blocks) run on v107 and v108 through
  `live_coordinate_run`. Every line's disposition and value, every question
  and its target, and every question link are the same once the four
  sentences are renamed. A code B wash-sale block shows the v108 sentence
  and never the v107 one. The other code B blocks read exactly as on v107.
  A sale with no loss trips both wash-sale blocks, so both sentences can
  appear on one line. A rendered page check runs the v108 code B
  short-term `CODE_W_ON_GAIN` model through `citation-walk.v1.html`. It
  shows the new sentence and the link line, with 0 section errors and 0
  first-read leaks.
