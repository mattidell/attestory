### 2. Statement anchor identity — PASS

`f1099b-covered-ltcg.bundle.json`'s `tax.us.2025.f1099b.statement-anchor` fact type declares `identity_keys`: `broker` (entity, `tax.us.f1099b-broker`), `statement` (entity, `tax.us.f1099b-statement`), `tax-year` (literal `2025`) — matching ADR-0052 Decision 1's `(tax-year, subject, broker-ref, logical-statement-ref)` (`subject` is implicit return-scope, consistent with the accepted `family.f1099div-2a.json`/box-2a member precedent, which likewise omits an explicit `subject` key). No `evidence`/`file`/`upload`/`document`/`scan` key is present in either the anchor's or the member's `identity_keys`.

Independently, beyond the committed schema-validity-only negative
(`fact-type.v2.covered-ltcg-txn-evidence-identity.json`, which only proves the
*generic* `fact-type.v2` schema doesn't structurally forbid an
`entity_kind` string containing "evidence" — confirmed by reading
`packages/schemas/kernel/fact-type.v2.schema.json`, whose `entity_kind` is an
unconstrained `{"type": "string", "minLength": 1}`), I traced the actual
production admission path. `packages/kernel/facts.py::facts_of` builds the
entire fact lattice exclusively by iterating each fact type's *declared*
`identity_keys` — a fact_id containing a key absent from that declaration can
never be generated by production. I confirmed this by constructing, via a
fresh script (not `fact_id_for` in isolation, but a full `apply_act` run),
an `assertion` act whose finding's `fact_id` smuggled an
`evidence-document` component into the member identity tuple:

```
fact_id_for("tax.us.2025.f1099b.covered-ltcg-txn", (
  ("broker","demo.broker.a"),("statement","demo.stmt.a"),
  ("transaction","demo.sale.001"),("evidence-document","demo.doc.999"),
  ("tax-year","2025")))
```

Result: `FindingModelError: finding references unknown fact:
tax.us.2025.f1099b.covered-ltcg-txn|broker=demo.broker.a,statement=demo.stmt.a,
transaction=demo.sale.001,evidence-document=demo.doc.999,tax-year=2025`. The
kernel rejects the substitution at admission, independent of and beyond the
committed schema-only negative.
