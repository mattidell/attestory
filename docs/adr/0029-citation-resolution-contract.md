# ADR 0029 — Citation Resolution Contract

- Status: **proposed** (foreman draft 2026-07-15; awaits owner ratification)
- Tier: 2
- Date: 2026-07-15

## Context

ADR-0012 left form-field citation references as inert opaque strings. Phase-state still records citation resolution as Not Decided. The inert ADR-0018 (single-author, no rival/committee/evaluation) is non-binding under ADR-0013.

The `citation-resolution` prototype (Track 0.c) produced two clean-room-separated designs and two independent committee reviews. Both designs make citations versioned package citizens with exact pins. Governance and adversary **reject** the incumbent’s resolver-side display canonicalization and overclaim of “verifiable” depth; both prefer the rival’s structural-and-adoption-only posture. Governance further prefers a **single** form-field citation pin and a four-family discriminated locator taxonomy. Evidence: `docs/prototypes/citation-resolution/evaluation-analysis.md`.

## Decision

1. **A citation is a first-class versioned content citizen.** Schema generation `citation.v1` (or successor) under ADR-0003: opaque `id`, `version`, authority-family identity, and family-specific locator fields. Citations are not unversioned inline blobs and not free-text residuals on residual-closed packages.

2. **Package membership is the sole adoption path.** Citation citizens are package members under role `citation` (shared role-canon growth per ADR-0027). No path inventory, directory walk, co-location, or side registry can make a citation adopted or executable. Exclusive execution projection applies (ADR-0027 decision 7).

3. **Attachment is exact pins.**
   - **Form-field (presentation):** at most **one** exact `{id, version}` citation pin (singular printed-location authority under ADR-0012). Multi-authority grounding belongs on computation, not the field.
   - **Rule artifact (computation):** optional **array** of unique exact citation pins — explanatory metadata only; must not alter `when`, `value`, `publishes`, blocking, or form-field dispositions.

4. **Authority families (v1).** Residual-closed content uses a discriminated family/locator model covering at least: US Code (`us-code`), IRS form editions (`irs-form`), IRS instructions (`irs-instructions`), and IRS publications (`irs-publication`) — or equivalent closed enum with the same discrimination. Soft, non-discriminated property bags that accept cross-family locators are not residual-closed. (Exact field names are schema detail; discrimination is normative.)

5. **Resolver contract is structural and adoption-only.** At package load / adoption the resolver:
   - validates each citation citizen against its published schema generation;
   - resolves every attachment pin to an exact package member;
   - checks registry-backed published bytes for package and citation citizens (ADR-0003 / ADR-0027 immutability);
   - accumulates contained issues (ADR-0006 decision 3) and marks the package **invalid for adoption/execution** if any citation defect is present.
   
   Successful attachments report **static resolution** only (e.g. `statically_resolved`). The resolver **must not** claim `legal_verified`, external corpus presence, live network fetch, or legal applicability. A future authority-corpus contract, if any, is a **separate versioned decision** and cannot silently widen this resolver.

6. **No runner-resident display canonicalization.** Citation citizens may carry human-facing labels as ordinary content fields if schema requires, but the load-time resolver does **not** embed IRC/IRS string-formatting templates or reject packages solely for “non-canonical display” generated by runner code. Presentation formatting, if productized later, is a separate rendering contract (Article 11).

7. **Residual-closed packages exclude opaque co-equal cites.** Generations admitted for residual-closed packages must not treat free-text `citation_ref` strings (form-field.v1 shape) as co-equal with structured pins. Migration windows, if any, are explicit, versioned, and temporary — not silent dual-read forever.

8. **Immutability.** Published citation `(id, version)` is immutable. Corrections publish a new version and update pins; in-place byte changes under the same version reject (Article 9).

## Consequences

- Track 5 implements citation schemas, package role/`admitted_schemas`, attachment fields on form-field.v2 and rule-artifact.v2, and load-time validation under this ADR — not ADR-0018.
- **PC1.** Goldens: opaque residual reject; malformed family/locator reject; unpinned citation reject; package with citation defect not adoptable; rewrite of citation bytes under same version reject; form-field multi-pin reject; rule pin does not change derivation outputs.
- **PC2.** Enforcement-grade discriminated family/locator schema (not a soft illustrative sketch).
- **PC3.** Publication-registry checks for citation citizen bytes.
- **PC4.** Role-canon admits `citation` monotonously.
- Inert ADR-0018 retained as superseded prior art.

## Alternatives Considered

- **Incumbent (it1): multi-cite form-fields + runner display canonicalization + “verifiable” language.** Rejected: ADR-0012 singular field authority (CIT-G4); Article 11 formatter (CIT-G5, CIT-A3/A7); false verifiability (CIT-G6, CIT-A2); soft load outcome (CIT-A9).
- **External legal corpus check at load as part of this contract.** Rejected: false confidence; out of static self-contained package posture (CIT-G6, CIT-A2). Defer to a separate decision if needed.
- **Path-based or co-located citation inventory.** Rejected: ADR-0027 sole package authority.
- **Inlining citation structure only on form-fields without citizens.** Rejected: both rivals and governance; breaks independent versioning and cross-attachment (CIT-G1).
