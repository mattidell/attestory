## Assignment

Design all three propositions against the committed contracts at `HEAD`:

1. **D1-P1.** The attachment citizen: what kind of thing it is; the states
   not-required / required-and-complete / required-and-incomplete, each a
   *published, walkable* disposition (not-required is a disposition, never
   silence); the >$1,500 requirement conditional as declared rule content
   over the existing interest and ordinary-dividend subtotals, with
   citation; where incompleteness blocks — the attachment, structurally
   unable to block sibling lines (show why by construction).
2. **D1-P2.** Part I/II payer-by-payer rows derived from 1099-INT/1099-DIV
   statement facts on record (payer identity + amount), subtotals, and a
   *declared* tie-out relation to lines 2b/3b (same closed family, same
   horizon); name the guard against a row set diverging from its line
   (supersession between reads, horizon advance).
3. **D1-P3.** Foreign-account and foreign-trust assertions as fact types on
   the existing taxpayer-assertion pattern, contributed via ADR-0032;
   yes-branch: 7a names the FinCEN-114 obligation (never produces it), 7b
   requires country content; a missing answer or missing country is factual
   incompleteness (case-3 posture).

## Required cases

The plan's six Gate-2 cases: (1) **hard trace, both outcomes, mandatory** —
required (dividends 1,600 / interest 900; walk inputs, threshold, citation,
per-trigger outcome) and not-required published with the same trace; state
the exactly-$1,500 boundary semantics with citation; (2) required-and-
complete publishes whole, pinned to every consumed fact; (3) **required-and-
incomplete, mandatory kill-case** — Part III absent, attachment blocks
walkably, lines 2b/3b/3a still publish, propagation impossible by
construction; (4) row/line tie-out and its divergence guard; (5) Part III
yes-branch, both branches; (6) **generalization, mandatory** — a Schedule D
stub (different trigger, different row facts) expressed with **zero
Schedule-B-specific schema surface**; if the shape needs modification,
redesign — do not annotate. Producer → authority → consumer → failure map
per proposition.
