# Retrospective: A Form 1099-B Bartering Amount Is Not Lost (2025)

Milestone key: f1099b-bartering. Plan:
`docs/phases/engine-breadth/milestones/f1099b-bartering.md`.
Closed 2026-11-19. Core v97, registry v95, release v95: five
input-question successors; no fact, rule, form field, schema or engine
change.

## What happened

The sale-family audit (N2) had left open which answer refuses a Form
1099-B box 13 bartering amount. P0 (a Claude Opus builder) found worse:
box 13 cannot be recorded, no question names bartering, and a filer who
answers the Schedule 1 questions as worded gets the same return as one
with no Form 1099-B, the bartering income silently missing. Of five
designs it kept the smallest honest one: tell the filer, in the shared
Schedule 1 lines 2a-6 question, to answer yes for a box 13 amount, which
refuses through the existing line 10 path. A Claude Sonnet builder
published it; the first content milestone to use the full-surface
replay showed only the package version changed on 775 recorded lists.
The fresh review accepted the change but named its limits plainly: a
workspace answered before v97 is not asked again, and P0's "no recorded
return was silently wrong" could not be proven because box 13 cannot be
recorded. Both are now stated and parked.

## What worked

- Treating "silently wrong" as the defect, not "not computed": a refusal
  with a reason is the honest outcome when computing is out of scope.
- The reviewer's scratch-copy mutations, which found a live test that
  did not notice a missing clause.

## What to change

- A census of recorded data cannot clear a defect in data the engine
  cannot record. Say so before using one as evidence.
- A wording fix reaches only filers who are still asked. When a fix
  lives in a question, name what happens to workspaces that already
  answered it.
