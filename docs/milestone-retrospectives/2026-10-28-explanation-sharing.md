# Retrospective — Explain a Shared Input Once

## What differed from the plan

The saved v1 presentations did not contain recursive explanation trees. They
saved roots and flattened citations, omitting intermediate lineage. The census
changed the persistence task: saving a complete shared graph adds evidence and
can enlarge the whole file even while replacing a much larger expanded walk.

Sharing also exposed an incoming-role bug in the old memo. A canonical finding
cannot own the role of its first caller; roles and full pin metadata belong to
uses. Producer references need their own identity, separate from findings.
Matching an ID is insufficient: saved loaders and browser traversal must keep
that kind distinction and the absence of a bare reference value.

## What it cost

One integrated build connected the walker, NPE, CLI, saved projection and
browser. The compatibility repairs showed why a textual consumer inventory
does not replace exercising those consumers. Tests that froze old omissions
needed a validated legacy view plus separate assertions for the new evidence.

Review followed the data through serialization and use: runtime checks had to
enforce the published schema, citation flattening had to stop repeating shared
work, and a reuse label had to lead to the earlier recorded explanation.

## Follow-ups

Recover the historical 9,885/218 observation only if its original scenario and
counting procedure become available; it is not an improvement baseline.
The browser investigation observed delayed readiness and disk-wait samples,
but did not establish the historical timeout's cause. Keep the bounded observer
for naturally occurring failures. No unchanged diagnostic rerun is selected.
Richer reader interaction and runtime profiling need a concrete new case.

## What should change in the next plan

Measure the caller output and the saved artifact separately before choosing a
representation. Preserve frozen bytes through explicit versioned adapters.
Test same-value wrong-root substitutions, incoming roles, versions and actual
pin relations: matching numbers and node counts do not establish fidelity.

A launcher that waits for readiness must also observe process exit and retain
safe failure evidence. A later green run establishes that candidate's result;
it does not explain an earlier failure or justify weakening its assertions.

Browser process ownership and scenario isolation have different lifetimes.
Reuse should preserve a fresh context while keeping restart evidence on a fresh
process. A startup limit must include every entrypoint and distinguish queue
wait from actual startup; otherwise it can merely move or hide contention.
Measure launch counts separately from warm-cache scenario timing. When a
one-shot command has no readiness event, state its conservative serialization
limit instead of claiming precise startup-only control.

Retaining a trace inside a subprocess is insufficient when its caller sees
only a generic failure and CI never saves the trace. Carry bounded failure
evidence across the actual ownership boundary. Keep process-lifecycle controls
deterministic when their claim requires no browser rendering, and preserve
real-browser evidence for isolation and application behavior. A timeout control
must separate startup from queue wait, just as the implementation does.
