# Retrospective: Form 8949 Code L for a Box 7 Loss (2025)

Milestone key: f8949-code-l. Plan:
`docs/phases/engine-breadth/milestones/f8949-code-l.md`.
Closed 2026-11-10 on P0.

## What happened

The milestone aimed to retire core v84's last box 7 refusal by reporting
a loss on a checked statement with Form 8949 code L. P0 quoted the 2025
instructions: the loss is wholly disallowed, column (g) carries it as a
positive amount and column (h) is zero. The amount is computable from
recorded proceeds and basis. The row is not: a Form 8949 row is a recorded
family member, and published attachment schemas can neither filter members
nor add a code. The builder stopped as chartered and named the smallest
change, a recording surface that records the disallowed sale in a code L
family.

The opening fix landed: a fast-lane test dropped the schema-compile memo
and the next derivation test on that worker paid the recompile inside its
timed call, which made `quick` fail on every PR. The recompile now runs in
teardown when the memo is empty.

## What worked

- A stop condition in the charter. P0 cost about $11 and no Track 0 or
  build was spent on a shape content cannot carry.
- Folding a standing CI defect into a milestone's opening commit.

## What to change

- Before chartering a new Form 8949 code, check whether the row needs a
  recorded family. Codes B and W did; code L does too. The P0 table of
  earlier codes would have shown it at planning time.

## Follow-ups

The code L recording change is an open owner-held question in the roadmap.
