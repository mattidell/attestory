# Retrospective: Line 12d's Boxes Are Shown (2025)

Milestone key: line12d-boxes. Plan:
`docs/phases/engine-breadth/milestones/line12d-boxes.md`.
Closed 2026-11-15. Core v90, registry v88, release v88. No ADR, no schema
or kernel change.

## What happened

Since core v88 the filer answers age and blindness, but the page showed
those answers only through line 12e. P0 found the content pattern already
existed (line 6d: a checked and a not-checked rule and field per box) and
one obstacle: the saved page drew only `checked` and raised an alert for
`not_checked`. The owner chose to teach the page to draw "not checked"
(Decision 1). Core v90 adds 17 members. The spouse boxes show on a joint
return, or on a separate return whose spouse condition is yes.

Track 0 passed every table on a 40-list sample; the full 775-list replay
ran in Track 1 (8 workers, about 22 minutes, no number changed). The
fresh review was ready with two should-fix findings: a spouse sentence
that named filing status beside a shown box, and "unanswered" test rows
that the shared helper had turned into false answers. Both were repaired.

Dispatch: grok for P0 (it stopped mid-rerun), a Claude Opus builder for
the decisions' prototype and Track 0, then grok for Track 1, the review
and the repair.

## What worked

- `tools/recorded_replay.py`: the full replay cost 22 minutes inside
  Track 1 instead of a three-hour unit of its own.
- The review ran its matrix without the shared helper, which is how it
  saw that the helper hid the unanswered case.

## What to change

- A shared helper that answers required questions must not be used by a
  case whose point is the unanswered state. Name a case "unanswered" only
  when its act list leaves the fact out.
- One inapplicable sentence per field serves two situations (hidden, and
  the other state of a shown box). Write it to be true in both, or give
  the hidden case its own disposition.
