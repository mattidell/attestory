# Retrospective — Planning with a Case Expert

## What differed from the plan

The plan expected the expert's challenges to be the main source of
correction. They were one source among four. The planner corrected its first
premise from its own evidence: it had expected a "no" to reduce the
deduction, and found it blocks. The expert added one distinction the planner
could not have found alone, and later pointed to an existing test. The two
independent reviews found further settled questions the planner had called
open. The owner's challenges found what everyone else had passed:
- an explanation's five explicit assumptions, which the expert had recorded;
- a proration premise no one had checked against the law;
- a lifecycle account that called supersession a retraction.

The facilitator added one more challenge. A test comment had been misread
as a current defect, and neither the expert nor the second reviewer caught
it.

The decisive changes came from challenges that pointed at artifacts and left
the diagnosis to the planner. When given that, the planner located each
problem in its own model and revised its own next actions. When a correction
came as a fact without a pointer to evidence, it changed one action but not
the habit behind it.

Withholding the expert's grounding from the planner kept the planner's first
model independent. It also delayed a fact the expert already held, until
after the first deliverable.

The plan itself gave the planner the four kinds of ground and their stakes.
So this episode could observe the planner applying that framework, finding
its own gaps and revising itself. It could not observe unaided recognition
of the stakes.

## What it cost

- **Participants:**
  - two Haiku channel probes;
  - one Sonnet case expert;
  - one Sonnet planner;
  - four Sonnet reviews: readiness, final, repaired model and publication.

  The planner and the expert each used several hundred thousand tokens
  across their resumed turns.
- **Owner turns:** two directions after launch, the first observations and
  the repair round.
- **Facilitator mediation:**
  - prompting the expert twice when a deliverable was complete;
  - relaying review findings, because reviewers do not message;
  - one launch made before checking a commit that the envelope gate had
    refused. The facilitator stopped it and relaunched.

## Follow-ups

- **The decisions in the adopted model.** Each is a product decision, and
  none is selected:
  - whether a known disqualifying loan answer should give a stated $0;
  - whether any of the five assumptions becomes answerable;
  - whether a filer-level $0 is explained by name.
- **Reader understanding.** No owner or independent reader has assessed the
  domain model.
- **The working-account practice** is carried into the next necessary
  development task, with the signals named in the plan's Outcome.

## What should change in the next plan

Ask the acting agent to write what it takes as given, what depends on it, and
what observation would change its next action. Then require the check to run
before any result is written. The structure helped the planner search in the
right place and notice when it was wrong. It did not stop the planner writing
a plausible result before looking.

Before calling a question open, search for the tests and pages that consume
the claim. Four of this episode's "unresolved" items were already settled by
committed tests that sat one search away from files the planner had open.

A fluent summary of a file is a warning sign, not a conclusion. The planner's
two most serious errors both came from summarizing toward the model it
already held:
- an omitted explanation bucket, in a file it had quoted three times;
- a misread test comment.

A challenge works best when it names the evidence to check and leaves the
diagnosis to the agent. Supplying the answer changes the document but not
the habit.
