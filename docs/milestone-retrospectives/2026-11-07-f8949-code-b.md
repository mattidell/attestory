# Retrospective: Broker Basis Corrections (2025)

Milestone key: f8949-code-b. Plan:
`docs/phases/engine-breadth/milestones/f8949-code-b.md`.
Closed 2026-11-07.

## What happened

P0 read the 2025 law. A covered sale whose reported basis is wrong stays
in box A or D, with the broker's basis in column (e) and the correction in
(g). Box B and E take the correct basis with -0- in (g), so code B is not
refused there, as the plan had expected.

P0 measured core v80, which publishes the broker's wrong gain when the
filer follows the Form 1099-B. It prototyped a content-only v81 with one
new grouped question.

Track 0 passed all six rows after four repairs: cross-term exclusivity, a
check that closes its families before reading, attachment counts, and
field words. It also found four v80 gaps that publish wrong or incomplete
returns. The foreman took those into Track 1.

The fresh review matched every hand-computed line. It found two more
inherited wrong-number paths:
- a zero-proceeds direct sale left line 7a at 0;
- four eligibility flags were never read.

It also found untrue field sentences and a red fast lane. The repair fixed
all of it in place on the unmerged v81. No engine, schema or recording
change was needed.

## What worked

- Reading the law before the design corrected the plan's assumption
  about boxes B and E.
- Wrong-number attacks on the neighbouring families, not only the new
  class, found five inherited v80 defects across Track 0 and the review.
  The code B work itself had none.
- Pinning reasons and rows from the first live test (last milestone's
  lesson) let the review see every changed v80 row, and let the repair
  drop 47 duplicate runs safely.

## What to change

- Each milestone on the Form 1099-B families has found more inherited
  defects in the same families: zero proceeds, duplicates, unread flags.
  A dedicated audit of every v80 sale family against the eligibility
  predicate would find them in one place instead of one per milestone.
- The lattice tests tripped the fast-lane budget one at a time across
  three PRs. When one test trips, measure the module and move every slow
  sibling at once.
- A full suite of about 31 minutes no longer fits one foreground command
  for a builder. It has to be split into shards and the counts summed.
