# Retrospective — Entry Loop on the Adopted Core

## What differed from the plan

The package supplies display identities, labels and bindings, but not the
entry loop's impact/comparison roles. Explicit v6/v70 profiles were needed
instead of selecting every numeric field. The bounded outcome is not support
for arbitrary future cores or usability validation.

The complete seed solved missing answers, but inherited a synthetic 2055
scope. Independent tracing showed that this was consumed as the authorization
and reporting year, not a harmless namespace. The v70 path now uses 2025;
legacy v6 remains unchanged.

## What it cost

One implementation and one semantic repair round followed the evidence probe.
Initial tests had no authorization grant, so they could not distinguish absent
authority from a wrong-year grant. A matching grant and wrong-year control
made that defect observable through the real coordinator.

## Follow-ups

- When evaluating v70 usability, construct a matching pack; do not apply the
  accepted v6 scorecard. The launcher currently says technical exercise only.
- When fixture-helper evolution makes regeneration unstable, decouple the
  generator from test internals. Runtime already reads only committed data.
- When improving correction guidance, provide a filer-facing reason for an
  incomplete result; this remains separate protocol/presentation work.

## What should change in the next plan

Trace contextual identifiers through consumers before preserving them by
analogy. A synthetic year can affect real authorization semantics. Test
computation and authorization currentness separately: a correct figure is not
permission to rely on it. Define display roles before selecting fields, and
distinguish supplied fixture answers from defaults and derived results.
