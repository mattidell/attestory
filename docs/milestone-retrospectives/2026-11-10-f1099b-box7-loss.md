# Retrospective: Form 1099-B Box 7 Read Only Beside a Loss (2025)

Milestone key: f1099b-box7-loss. Plan:
`docs/phases/engine-breadth/milestones/f1099b-box7-loss.md`.
Closed 2026-11-10.

## What happened

Core v83 refused any Form 1099-B statement whose box 7 was answered "yes".
Box 7 changes the result only where a sale is at a loss, so core v84
derives a verdict per sale and a loss check per sale family. A checked
statement with only gains or zeros computes; one loss on it blocks
Schedule D line 16 and asks nothing. The code L adjustment that would
disallow the loss is not computed.

P0 designed the verdict and check from a scratch core and decided to keep
line 16's eight sale-count requirements, so every recorded v83 return
stays identical. Track 0 passed all six rows and showed that eight
verdicts alone cannot stand in for the eight checks (closed-empty and
one-family returns fail). Track 1 published the prototype citizens
byte-identically.

The fresh review computed the cases by hand and found no wrong number. Its
should-fix: on a loss the filer read a sentence naming two causes that
were false of that return. A reason naming only the loss needs a
derivation change, because the projector attaches reasons only from a
selection or a closure question and line 16 must stay a value rule. The
repair made the explanation a true disjunction and dropped 28 duplicate
coordinate runs.

## What worked

- Keeping the old requirements (Decision 5). The 298-run comparison was
  identical with nothing to explain.
- Trying the smaller shape in Track 0 rather than arguing it. The eight-rule
  trial failed on measured cases.
- Resuming the builder's grok session for the repair: $8 against $9 for
  Track 1, with no re-reading.
